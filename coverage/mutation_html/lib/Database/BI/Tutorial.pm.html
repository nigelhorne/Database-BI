    8: # ---------------------------------------------------------------------------
    9: # The tutorial that the application shows at GET /tutorial.
   10: #
   11: # This is deliberately data, not a long HTML file.  A chapter is one feature,
   12: # and adding a feature means adding one hash to @CHAPTERS.  The template
   13: # (templates/web/en/tutorial.html.tt) knows how to show every field, so a new
   14: # chapter needs no template change.
   15: #
   16: # To add a chapter:
   17: #   1. Copy the shape of a chapter below.
   18: #   2. Give it a unique id, a part, a title, a one-sentence lead and short
   19: #      numbered steps.
   20: #   3. List the GET page routes that it covers in routes => [ ... ].
   21: #      t/tutorial.t fails when a GET page in lib/Database/BI.pm has no
   22: #      chapter, so this list is a reminder that cannot be forgotten.
   23: #   4. Use short sentences and common words.  The test also fails a lead,
   24: #      step or tip that is longer than 25 words.
   25: #
   26: # A route that is not a page for readers (JSON for a panel, for example) goes
   27: # in %EXEMPT_ROUTES with a reason, instead of getting a chapter.
   28: # ---------------------------------------------------------------------------

  804: =head1 NAME
  805: 
  806: Database::BI::Tutorial - the chapters of the in-application tutorial
  807: 
  808: =head1 DESCRIPTION
  809: 
  810: The tutorial that the application shows at C<GET /tutorial> is built from the
  811: data in this module.  A chapter is one feature: a title, a short lead, numbered
  812: steps, and the C<routes> that it covers.  The template renders the chapters in
  813: order, so adding a feature means adding a hash here, not editing HTML.
  814: 
  815: A chapter may also have a C<walkthrough>: a worked example with a C<title>, an
  816: C<intro>, a list of C<steps> that each say what to C<do> and what to C<see>,
  817: and a C<result>.  The template shows it as one box, and the contents marks the
  818: chapter so a reader can find it.
  819: 
  820: C<t/tutorial.t> checks that every GET page in L<Database::BI> is either covered
  821: by a chapter or listed in C<exempt_routes()> with a reason.  Keep the sentences
  822: short: the same test fails a lead, step, tip or walk-through sentence longer
  823: than 25 words.
  824: 
  825: C<chapter_for_action()> maps a controller action to the chapter that helps with
  826: that page.  The application calls it from a C<before_render> hook and the shared
  827: layout shows the result as a C<Help: ...> link beside the main Tutorial link.
  828: A new page action belongs in C<%ACTION_CHAPTERS>; the test fails until it is
  829: there.
