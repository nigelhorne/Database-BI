    9: # The tutorial that the application shows at GET /tutorial.
   10: #
   11: # This is deliberately data, not a long HTML file.  A chapter is one feature,
   12: # and adding a feature means adding one hash to @CHAPTERS.  The template
   13: # (templates/web/en/tutorial.html.tt) knows how to show every field, so a new
   14: # chapter needs no template change.
   15: #
   16: # To add a chapter:
   17: #   1. Copy the shape of a chapter below.
   18: #   2. Give it a unique id, a part, a title, a one-sentence lead and short
   19: #      numbered steps.
   20: #   3. List the GET page routes that it covers in routes => [ ... ].
   21: #      t/tutorial.t fails when a GET page in lib/Database/BI.pm has no
   22: #      chapter, so this list is a reminder that cannot be forgotten.
   23: #   4. Use short sentences and common words.  The test also fails a lead,
   24: #      step or tip that is longer than 25 words.
   25: #
   26: # A route that is not a page for readers (JSON for a panel, for example) goes
   27: # in %EXEMPT_ROUTES with a reason, instead of getting a chapter.
   28: # ---------------------------------------------------------------------------

 1182: 
 1183: Database::BI::Tutorial - the chapters of the in-application tutorial
 1184: 
 1185: =head1 SYNOPSIS
 1186: 
 1187:   use Database::BI::Tutorial;
 1188:

 1196: =head1 DESCRIPTION
 1197: 
 1198: The tutorial that the application shows at C<GET /tutorial> is built from the
 1199: data in this module.  A chapter is one feature: a title, a short lead, numbered
 1200: steps, and the C<routes> that it covers.  The template renders the chapters in
 1201: order, so adding a feature means adding a hash here, not editing HTML.
 1202: 
 1203: A chapter may also have a C<walkthrough>: a worked example with a C<title>, an
 1204: C<intro>, a list of C<steps> that each say what to C<do> and what to C<see>,
 1205: and a C<result>.  The template shows it as one box, and the contents marks the
 1206: chapter so a reader can find it.
 1207: 
 1208: C<t/tutorial.t> checks that every GET page in L<Database::BI> is either covered
 1209: by a chapter or listed in C<exempt_routes()> with a reason.  Keep the sentences
 1210: short: the same test fails a lead, step, tip or walk-through sentence longer
 1211: than 25 words.
 1212: 
 1213: C<chapter_for_action()> maps a controller action to the chapter that helps with
 1214: that page.  The application calls it from a C<before_render> hook and the shared
 1215: layout shows the result as a C<Help: ...> link beside the main Tutorial link.
 1216: A new page action belongs in C<%ACTION_CHAPTERS>; the test fails until it is
 1217: there.
 1218:

 1221: Each is called as a class method or a plain function; none takes arguments
 1222: except C<chapter_for_action>.  The returned structures are the module's own
 1223: data: read them, do not change them.
