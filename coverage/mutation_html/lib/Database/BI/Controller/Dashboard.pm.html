 1572: =head2 Filter operators
 1573: 
 1574: The C<f=col:op:val> filter spec supports:
 1575: 
 1576:   eq        case-insensitive string equality
 1577:   ne        case-insensitive string inequality
 1578:   contains  case-insensitive substring match
 1579:   starts    case-insensitive prefix match
 1580:   lt        numeric less-than
 1581:   le        numeric less-than-or-equal
 1582:   gt        numeric greater-than
 1583:   ge        numeric greater-than-or-equal
 1584:   empty     cell is undef or empty string (val ignored)
 1585:   notempty  cell is defined and non-empty (val ignored)
 1586: 
 1587: The colon separator is split with a limit of 3, so values may themselves
 1588: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1589: 
 1590: =head1 COMMON PITFALLS
 1591: 
 1592: These are the most common mistakes when working with this controller.
 1593: 
 1594: =over 4
 1595: 
 1596: =item B<SQLite files must use the .sql extension, not .sqlite>
 1597: 
 1598: C<Database::Abstraction> (the data-reading library) probes for a file called
 1599: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1600: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1601: rename it to C<inventory.sql> or it will not appear in the file browser and
 1602: will return 404 when opened.
 1603: 
 1604: =item B<Filter values that contain a colon still work>
 1605: 
 1606: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1607: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1608: the filter still works because the C<col:op:val> spec is split on the B<first
 1609: two> colons only -- the rest of the string becomes the value.
 1610: 
 1611:   # This correctly matches "14:30:00" in the start_time column:
 1612:   ?f=start_time:eq:14:30:00
 1613: 
 1614: =item B<Left join keeps only the FIRST matching right-table row>
 1615: 
 1616: When the right table has two rows with the same join key, only the first one
 1617: (in file order) is used.  The second is silently ignored.  If you need all
 1618: matches, consider pre-processing your data so join keys are unique.
 1619: 
 1620: =item B<Export format comes from the filename extension, not a Content-Type header>
 1621: 
 1622: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1623: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1624: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1625: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1626: ignored entirely.
 1627: 
 1628: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1629: 
 1630: If you add a stash variable with a name starting with C<_> (for example,
 1631: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1632: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1633: is active.  Always use names that start with a letter.
 1634: 
 1635: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1636: 
 1637: If you pass an operator that is not in the supported list (for example C<regex>
 1638: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1639: error is produced.  This is intentional so that future operators can be added
 1640: without breaking existing clients that read a wider response.
 1641: 
 1642: =item B<Uploading a file does not clean up automatically>
 1643: 
 1644: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1645: application's home directory and are B<never deleted automatically>.  They
 1646: accumulate until you manually remove the C<.uploads/> directory.  This is
 1647: intentional for a single-user local tool, but you should be aware of it on
 1648: long-running servers.
 1649: 
 1650: =item B<Open C<data/> tables by name; open other files by absolute path>
 1651: 
 1652: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1653: To open a file from anywhere else on the filesystem, use C<open_file>
 1654: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1655: are not interchangeable.
 1656:
