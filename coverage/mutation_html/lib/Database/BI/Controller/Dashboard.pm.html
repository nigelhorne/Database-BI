 2994: 
 2995: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2996: server-side after all joins.  Multiple C<f=> params are applied in order
 2997: (AND semantics).
 2998: 
 2999: The colon separator is split with a limit of 3, so values may themselves
 3000: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 3001: C<f=start_time:eq:14:30:00>).
 3002: 
 3003: B<Supported operators:>
 3004: 
 3005:   eq        case-insensitive string equality
 3006:   ne        case-insensitive string inequality
 3007:   contains  case-insensitive substring match
 3008:   starts    case-insensitive prefix match
 3009:   lt        numeric less-than
 3010:   le        numeric less-than-or-equal
 3011:   gt        numeric greater-than
 3012:   ge        numeric greater-than-or-equal
 3013:   empty     cell is undef or empty string (val ignored)
 3014:   notempty  cell is defined and non-empty (val ignored)
 3015: 
 3016: B<Quick-filter bar (table view):>
 3017: 
 3018: A filter row below the toolbar lets the user pick a column, operator, and
 3019: value and press "Apply filter" (or Enter) to add a condition without
 3020: opening any panel.  The current URL is updated with the new C<f=> param
 3021: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 3022: preserved automatically via the browser C<URL> API.
 3023: 
 3024: Active filter chips appear in the toolbar.  Each chip has an individual

 3029:

 3034: =head1 COMMON PITFALLS
 3035: 
 3036: These are the most common mistakes when working with this controller.
 3037: 
 3038: =over 4
 3039: 
 3040: =item B<SQLite files must use the .sql extension, not .sqlite>
 3041: 
 3042: C<Database::Abstraction> (the data-reading library) probes for a file called
 3043: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 3044: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 3045: rename it to C<inventory.sql> or it will not appear in the file browser and
 3046: will return 404 when opened.
 3047: 
 3048: =item B<Filter values that contain a colon still work>
 3049: 
 3050: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 3051: if your value itself contains a colon (for example, a time like C<14:30:00>),
 3052: the filter still works because the C<col:op:val> spec is split on the B<first
 3053: two> colons only -- the rest of the string becomes the value.
 3054: 
 3055:   # This correctly matches "14:30:00" in the start_time column:
 3056:   ?f=start_time:eq:14:30:00
 3057: 
 3058: =item B<Left join keeps only the FIRST matching right-table row>
 3059: 
 3060: When the right table has two rows with the same join key, only the first one
 3061: (in file order) is used.  The second is silently ignored.  If you need all
 3062: matches, consider pre-processing your data so join keys are unique.
 3063: 
 3064: =item B<Export format comes from the filename extension, not a Content-Type header>
 3065: 
 3066: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 3067: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 3068: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 3069: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 3070: ignored entirely.
 3071: 
 3072: =item B<Template Toolkit variables starting with underscore are silently dropped>
 3073: 
 3074: If you add a stash variable with a name starting with C<_> (for example,
 3075: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 3076: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 3077: is active.  Always use names that start with a letter.
 3078: 
 3079: =item B<_apply_filter_spec always passes all records through for unknown operators>
 3080: 
 3081: If you pass an operator that is not in the supported list (for example C<regex>
 3082: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 3083: error is produced.  This is intentional so that future operators can be added
 3084: without breaking existing clients that read a wider response.
 3085: 
 3086: =item B<Uploaded files are evicted automatically, but not immediately>
 3087: 
 3088: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 3089: application home directory.  C<Database::BI> evicts upload subdirectories
 3090: whose modification time is older than 24 hours B<on every server startup>.
 3091: Between restarts, files accumulate.  For an immediate full purge (regardless
 3092: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 3093: button in the UI.
 3094: 
 3095: =item B<Open C<data/> tables by name; open other files by absolute path>
 3096: 
 3097: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 3098: To open a file from anywhere else on the filesystem, use C<open_file>
 3099: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 3100: are not interchangeable.
