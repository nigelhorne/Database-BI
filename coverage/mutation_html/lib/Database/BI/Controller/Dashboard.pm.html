 2343: 	}

 2356: 	                                : "Count by $x_col and $y_col";

 2690: =head2 Filter operators and the quick-filter bar
 2691: 
 2692: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2693: server-side after all joins.  Multiple C<f=> params are applied in order
 2694: (AND semantics).
 2695: 
 2696: The colon separator is split with a limit of 3, so values may themselves
 2697: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2698: C<f=start_time:eq:14:30:00>).
 2699: 
 2700: B<Supported operators:>
 2701: 
 2702:   eq        case-insensitive string equality
 2703:   ne        case-insensitive string inequality
 2704:   contains  case-insensitive substring match
 2705:   starts    case-insensitive prefix match
 2706:   lt        numeric less-than
 2707:   le        numeric less-than-or-equal
 2708:   gt        numeric greater-than
 2709:   ge        numeric greater-than-or-equal
 2710:   empty     cell is undef or empty string (val ignored)
 2711:   notempty  cell is defined and non-empty (val ignored)
 2712: 
 2713: B<Quick-filter bar (table view):>
 2714: 
 2715: A filter row below the toolbar lets the user pick a column, operator, and
 2716: value and press "Apply filter" (or Enter) to add a condition without
 2717: opening any panel.  The current URL is updated with the new C<f=> param
 2718: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2719: preserved automatically via the browser C<URL> API.
 2720: 
 2721: Active filter chips appear in the toolbar.  Each chip has an individual
 2722: x-button to remove just that condition.  The "x Clear filters" link
 2723: removes all C<f=> params at once.
 2724: 
 2725: B<Drill-down from pie chart:>
 2726: 
 2727: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2728: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2729: rows behind any slice without manually typing a filter.

 2731: =head1 COMMON PITFALLS
 2732: 
 2733: These are the most common mistakes when working with this controller.
 2734: 
 2735: =over 4
 2736: 
 2737: =item B<SQLite files must use the .sql extension, not .sqlite>
 2738: 
 2739: C<Database::Abstraction> (the data-reading library) probes for a file called
 2740: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2741: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2742: rename it to C<inventory.sql> or it will not appear in the file browser and
 2743: will return 404 when opened.
 2744: 
 2745: =item B<Filter values that contain a colon still work>
 2746: 
 2747: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2748: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2749: the filter still works because the C<col:op:val> spec is split on the B<first
 2750: two> colons only -- the rest of the string becomes the value.
 2751: 
 2752:   # This correctly matches "14:30:00" in the start_time column:
 2753:   ?f=start_time:eq:14:30:00
 2754: 
 2755: =item B<Left join keeps only the FIRST matching right-table row>
 2756: 
 2757: When the right table has two rows with the same join key, only the first one
 2758: (in file order) is used.  The second is silently ignored.  If you need all
 2759: matches, consider pre-processing your data so join keys are unique.
 2760: 
 2761: =item B<Export format comes from the filename extension, not a Content-Type header>
 2762: 
 2763: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2764: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2765: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2766: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2767: ignored entirely.
 2768: 
 2769: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2770: 
 2771: If you add a stash variable with a name starting with C<_> (for example,
 2772: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2773: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2774: is active.  Always use names that start with a letter.
 2775: 
 2776: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2777: 
 2778: If you pass an operator that is not in the supported list (for example C<regex>
 2779: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2780: error is produced.  This is intentional so that future operators can be added
 2781: without breaking existing clients that read a wider response.
 2782: 
 2783: =item B<Uploaded files are evicted automatically, but not immediately>
 2784: 
 2785: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2786: application home directory.  C<Database::BI> evicts upload subdirectories
 2787: whose modification time is older than 24 hours B<on every server startup>.
 2788: Between restarts, files accumulate.  For an immediate full purge (regardless
 2789: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2790: button in the UI.
 2791: 
 2792: =item B<Open C<data/> tables by name; open other files by absolute path>
 2793: 
 2794: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2795: To open a file from anywhere else on the filesystem, use C<open_file>
 2796: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2797: are not interchangeable.
 2798: 
 2799: =back
