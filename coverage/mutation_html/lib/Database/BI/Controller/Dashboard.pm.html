 2382: 
 2383: Each row's category value (C<cat=>) is used as a slice label; the numeric
 2384: value column (C<val=>) is summed per category.  Accounting-notation
 2385: negatives such as C<(1,234.56)> are handled automatically.  Slices are
 2386: sorted by total descending; when there are more than 12 distinct categories
 2387: the smallest ones are collapsed into a single "Other" slice.
 2388: 
 2389: Clicking any slice or legend entry navigates back to the table view with
 2390: an C<f=cat:eq:value> filter applied automatically, so the user can drill
 2391: into the data behind a slice without leaving the application.
 2392:

 2394:

 2398:   cat=<col>   string   Category column name (required; used as slice labels).

 2405: 
 2406:   200 text/html   TT-rendered pie chart page containing:

 2412:                   - Slice count (e.g. "7 slices").

 2422: 
 2423:   cat=    Any column name that exists in the result set.  Cell values are

 2432:   donut=  Any truthy value (e.g. "1") enables the donut hole.  Absent or

 2500: =head2 Filter operators and the quick-filter bar
 2501: 
 2502: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2503: server-side after all joins.  Multiple C<f=> params are applied in order
 2504: (AND semantics).
 2505: 
 2506: The colon separator is split with a limit of 3, so values may themselves
 2507: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2508: C<f=start_time:eq:14:30:00>).
 2509: 
 2510: B<Supported operators:>
 2511: 
 2512:   eq        case-insensitive string equality
 2513:   ne        case-insensitive string inequality
 2514:   contains  case-insensitive substring match
 2515:   starts    case-insensitive prefix match
 2516:   lt        numeric less-than
 2517:   le        numeric less-than-or-equal
 2518:   gt        numeric greater-than
 2519:   ge        numeric greater-than-or-equal
 2520:   empty     cell is undef or empty string (val ignored)
 2521:   notempty  cell is defined and non-empty (val ignored)
 2522: 
 2523: B<Quick-filter bar (table view):>
 2524: 
 2525: A filter row below the toolbar lets the user pick a column, operator, and
 2526: value and press "Apply filter" (or Enter) to add a condition without
 2527: opening any panel.  The current URL is updated with the new C<f=> param
 2528: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2529: preserved automatically via the browser C<URL> API.
 2530: 
 2531: Active filter chips appear in the toolbar.  Each chip has an individual
 2532: x-button to remove just that condition.  The "x Clear filters" link
 2533: removes all C<f=> params at once.
 2534: 
 2535: B<Drill-down from pie chart:>
 2536: 
 2537: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2538: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2539: rows behind any slice without manually typing a filter.

 2541: =head1 COMMON PITFALLS
 2542: 
 2543: These are the most common mistakes when working with this controller.
 2544: 
 2545: =over 4
 2546: 
 2547: =item B<SQLite files must use the .sql extension, not .sqlite>
 2548: 
 2549: C<Database::Abstraction> (the data-reading library) probes for a file called
 2550: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2551: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2552: rename it to C<inventory.sql> or it will not appear in the file browser and
 2553: will return 404 when opened.
 2554: 
 2555: =item B<Filter values that contain a colon still work>
 2556: 
 2557: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2558: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2559: the filter still works because the C<col:op:val> spec is split on the B<first
 2560: two> colons only -- the rest of the string becomes the value.
 2561: 
 2562:   # This correctly matches "14:30:00" in the start_time column:
 2563:   ?f=start_time:eq:14:30:00
 2564: 
 2565: =item B<Left join keeps only the FIRST matching right-table row>
 2566: 
 2567: When the right table has two rows with the same join key, only the first one
 2568: (in file order) is used.  The second is silently ignored.  If you need all
 2569: matches, consider pre-processing your data so join keys are unique.
 2570: 
 2571: =item B<Export format comes from the filename extension, not a Content-Type header>
 2572: 
 2573: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2574: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2575: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2576: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2577: ignored entirely.
 2578: 
 2579: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2580: 
 2581: If you add a stash variable with a name starting with C<_> (for example,
 2582: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2583: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2584: is active.  Always use names that start with a letter.
 2585: 
 2586: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2587: 
 2588: If you pass an operator that is not in the supported list (for example C<regex>
 2589: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2590: error is produced.  This is intentional so that future operators can be added
 2591: without breaking existing clients that read a wider response.
 2592: 
 2593: =item B<Uploaded files are evicted automatically, but not immediately>
 2594: 
 2595: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2596: application home directory.  C<Database::BI> evicts upload subdirectories
 2597: whose modification time is older than 24 hours B<on every server startup>.
 2598: Between restarts, files accumulate.  For an immediate full purge (regardless
 2599: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2600: button in the UI.
 2601: 
 2602: =item B<Open C<data/> tables by name; open other files by absolute path>
 2603: 
 2604: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2605: To open a file from anywhere else on the filesystem, use C<open_file>
 2606: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2607: are not interchangeable.
 2608: 
 2609: =back

 2616:
