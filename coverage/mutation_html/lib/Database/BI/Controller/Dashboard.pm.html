 2243: =head2 Filter operators
 2244: 
 2245: The C<f=col:op:val> filter spec supports:
 2246: 
 2247:   eq        case-insensitive string equality
 2248:   ne        case-insensitive string inequality
 2249:   contains  case-insensitive substring match
 2250:   starts    case-insensitive prefix match
 2251:   lt        numeric less-than
 2252:   le        numeric less-than-or-equal
 2253:   gt        numeric greater-than
 2254:   ge        numeric greater-than-or-equal
 2255:   empty     cell is undef or empty string (val ignored)
 2256:   notempty  cell is defined and non-empty (val ignored)
 2257: 
 2258: The colon separator is split with a limit of 3, so values may themselves
 2259: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 2260: 
 2261: =head1 COMMON PITFALLS
 2262: 
 2263: These are the most common mistakes when working with this controller.
 2264: 
 2265: =over 4
 2266: 
 2267: =item B<SQLite files must use the .sql extension, not .sqlite>
 2268: 
 2269: C<Database::Abstraction> (the data-reading library) probes for a file called
 2270: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2271: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2272: rename it to C<inventory.sql> or it will not appear in the file browser and
 2273: will return 404 when opened.
 2274: 
 2275: =item B<Filter values that contain a colon still work>
 2276: 
 2277: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2278: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2279: the filter still works because the C<col:op:val> spec is split on the B<first
 2280: two> colons only -- the rest of the string becomes the value.
 2281: 
 2282:   # This correctly matches "14:30:00" in the start_time column:
 2283:   ?f=start_time:eq:14:30:00
 2284: 
 2285: =item B<Left join keeps only the FIRST matching right-table row>
 2286: 
 2287: When the right table has two rows with the same join key, only the first one
 2288: (in file order) is used.  The second is silently ignored.  If you need all
 2289: matches, consider pre-processing your data so join keys are unique.
 2290: 
 2291: =item B<Export format comes from the filename extension, not a Content-Type header>
 2292: 
 2293: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2294: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2295: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2296: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2297: ignored entirely.
 2298: 
 2299: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2300: 
 2301: If you add a stash variable with a name starting with C<_> (for example,
 2302: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2303: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2304: is active.  Always use names that start with a letter.
 2305: 
 2306: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2307: 
 2308: If you pass an operator that is not in the supported list (for example C<regex>
 2309: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2310: error is produced.  This is intentional so that future operators can be added
 2311: without breaking existing clients that read a wider response.
 2312: 
 2313: =item B<Uploading a file does not clean up automatically>
 2314: 
 2315: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2316: application's home directory and are B<never deleted automatically>.  They
 2317: accumulate until you manually remove the C<.uploads/> directory.  This is
 2318: intentional for a single-user local tool, but you should be aware of it on
 2319: long-running servers.
 2320: 
 2321: =item B<Open C<data/> tables by name; open other files by absolute path>
 2322: 
 2323: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2324: To open a file from anywhere else on the filesystem, use C<open_file>
 2325: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2326: are not interchangeable.
 2327: 
 2328: =back
