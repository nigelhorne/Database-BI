 3099:   200 text/plain  "No plottable data" when every row has a non-numeric or
 3100:                   missing value column (HTTP 200, not 4xx, so the page can
 3101:                   render a friendly message).
 3102: 
 3103:   400 text/plain  C<cat=> or C<val=> absent, or named column not found.
 3104:   404 text/plain  Data source could not be opened.
 3105: 
 3106: =head4 DOMAIN CONSTRAINTS
 3107: 
 3108:   cat=    Any column name that exists in the result set.  Cell values are
 3109:           used verbatim as slice labels.  Empty-string cells are skipped.
 3110: 
 3111:   val=    Must be a column whose cells contain numbers (after stripping
 3112:           currency symbols, commas, and handling accounting-notation negatives).
 3113:           Rows where the value is still non-numeric after stripping are skipped.
 3114:           Negative totals are included in the chart (slice values may be negative
 3115:           if the source data contains credits or reversals).
 3116: 
 3117:   donut=  Any truthy value (e.g. "1") enables the donut hole.  Absent or
 3118:           "0" renders a solid pie.
 3119: 
 3120: =head3 MESSAGES
 3121: 
 3122:   Missing cat or val column parameter    C<cat=> or C<val=> query param absent.
 3123:   Column not found: <name>               Named column absent from the result set.
 3124:   Could not open data source             Left-table spec unresolvable or 404.
 3125:   No plottable data: ...                 All rows lack a valid numeric value.

 3127: =head3 EXAMPLE
 3128: 
 3129:   GET /pie?l=table:sales&cat=region&val=amount&back=/view/sales
 3130: 
 3131: Renders a pie chart of total C<amount> per C<region>.  Clicking the
 3132: "North" slice navigates to C</view/sales?f=region:eq:North>.
 3133: 
 3134: With a donut hole:
 3135: 
 3136:   GET /pie?l=table:sales&cat=region&val=amount&donut=1

 3139: 
 3140:   pie_view : Controller x Params -> HTML | Error
 3141: 
 3142:   let pipeline = run_export_pipeline(l, j, f, d)
 3143:   let totals   = { cat => sum { val(row) | row in pipeline.records,

 3147:   pre  cat in params /\ val in params     else 400

 3185: =head2 Filter operators and the quick-filter bar
 3186: 
 3187: Filters are expressed as C<f=col:op:val> query parameters and are applied
 3188: server-side after all joins.  Multiple C<f=> params are applied in order
 3189: (AND semantics).
 3190: 
 3191: The colon separator is split with a limit of 3, so values may themselves
 3192: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 3193: C<f=start_time:eq:14:30:00>).
 3194: 
 3195: B<Supported operators:>
 3196: 
 3197:   eq        case-insensitive string equality
 3198:   ne        case-insensitive string inequality
 3199:   contains  case-insensitive substring match
 3200:   starts    case-insensitive prefix match
 3201:   lt        numeric less-than
 3202:   le        numeric less-than-or-equal
 3203:   gt        numeric greater-than
 3204:   ge        numeric greater-than-or-equal
 3205:   empty     cell is undef or empty string (val ignored)
 3206:   notempty  cell is defined and non-empty (val ignored)
 3207: 
 3208: B<Quick-filter bar (table view):>
 3209: 
 3210: A filter row below the toolbar lets the user pick a column, operator, and
 3211: value and press "Apply filter" (or Enter) to add a condition without
 3212: opening any panel.  The current URL is updated with the new C<f=> param
 3213: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 3214: preserved automatically via the browser C<URL> API.
 3215: 
 3216: Active filter chips appear in the toolbar.  Each chip has an individual
 3217: x-button to remove just that condition.  The "x Clear filters" link
 3218: removes all C<f=> params at once.
 3219: 
 3220: B<Drill-down from pie chart:>
 3221: 
 3222: Clicking a pie slice or legend entry on C</pie> navigates to the table
 3223: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 3224: rows behind any slice without manually typing a filter.

 3226: =head1 COMMON PITFALLS
 3227: 
 3228: These are the most common mistakes when working with this controller.
 3229: 
 3230: =over 4
 3231: 
 3232: =item B<SQLite files must use the .sql extension, not .sqlite>
 3233: 
 3234: C<Database::Abstraction> (the data-reading library) probes for a file called
 3235: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 3236: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 3237: rename it to C<inventory.sql> or it will not appear in the file browser and
 3238: will return 404 when opened.
 3239: 
 3240: =item B<Filter values that contain a colon still work>
 3241: 
 3242: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 3243: if your value itself contains a colon (for example, a time like C<14:30:00>),
 3244: the filter still works because the C<col:op:val> spec is split on the B<first
 3245: two> colons only -- the rest of the string becomes the value.
 3246: 
 3247:   # This correctly matches "14:30:00" in the start_time column:
 3248:   ?f=start_time:eq:14:30:00
 3249: 
 3250: =item B<Left join keeps only the FIRST matching right-table row>
 3251: 
 3252: When the right table has two rows with the same join key, only the first one
 3253: (in file order) is used.  The second is silently ignored.  If you need all
 3254: matches, consider pre-processing your data so join keys are unique.
 3255: 
 3256: =item B<Export format comes from the filename extension, not a Content-Type header>
 3257: 
 3258: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 3259: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 3260: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 3261: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 3262: ignored entirely.
 3263: 
 3264: =item B<Template Toolkit variables starting with underscore are silently dropped>
 3265: 
 3266: If you add a stash variable with a name starting with C<_> (for example,
 3267: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 3268: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 3269: is active.  Always use names that start with a letter.
 3270: 
 3271: =item B<_apply_filter_spec always passes all records through for unknown operators>
 3272: 
 3273: If you pass an operator that is not in the supported list (for example C<regex>
 3274: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 3275: error is produced.  This is intentional so that future operators can be added
 3276: without breaking existing clients that read a wider response.
 3277: 
 3278: =item B<Uploaded files are evicted automatically, but not immediately>
 3279: 
 3280: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 3281: application home directory.  C<Database::BI> evicts upload subdirectories
 3282: whose modification time is older than 24 hours B<on every server startup>.
 3283: Between restarts, files accumulate.  For an immediate full purge (regardless
 3284: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 3285: button in the UI.
 3286: 
 3287: =item B<Open C<data/> tables by name; open other files by absolute path>
 3288: 
 3289: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 3290: To open a file from anywhere else on the filesystem, use C<open_file>
 3291: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 3292: are not interchangeable.
 3293: 
 3294: =back
