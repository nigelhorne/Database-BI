 3906:   400 text/plain  C<cat=> or C<val=> absent, or named column not found.
 3907:   404 text/plain  Data source could not be opened.
 3908: 
 3909: =head4 DOMAIN CONSTRAINTS
 3910: 
 3911:   cat=    Any column name that exists in the result set.  Cell values are
 3912:           used verbatim as slice labels.  Empty-string cells are skipped.
 3913: 
 3914:   val=    Must be a column whose cells contain numbers (after stripping
 3915:           currency symbols, commas, and handling accounting-notation negatives).
 3916:           Rows where the value is still non-numeric after stripping are skipped.
 3917:           Negative totals are included in the chart (slice values may be negative
 3918:           if the source data contains credits or reversals).
 3919: 
 3920:   donut=  Any truthy value (e.g. "1") enables the donut hole.  Absent or
 3921:           "0" renders a solid pie.
 3922: 
 3923: =head3 MESSAGES
 3924: 
 3925:   Missing cat or val column parameter    C<cat=> or C<val=> query param absent.
 3926:   Column not found: <name>               Named column absent from the result set.
 3927:   Could not open data source             Left-table spec unresolvable or 404.
 3928:   No plottable data: ...                 All rows lack a valid numeric value.
 3929: 
 3930: =head3 EXAMPLE
 3931: 
 3932:   GET /pie?l=table:sales&cat=region&val=amount&back=/view/sales
 3933: 
 3934: Renders a pie chart of total C<amount> per C<region>.  Clicking the
 3935: "North" slice navigates to C</view/sales?f=region:eq:North>.
 3936: 
 3937: With a donut hole:
 3938: 
 3939:   GET /pie?l=table:sales&cat=region&val=amount&donut=1
 3940: 
 3941: =head3 FORMAL SPECIFICATION
 3942: 
 3943:   pie_view : Controller x Params -> HTML | Error
 3944: 
 3945:   let pipeline = run_export_pipeline(l, j, f, d)
 3946:   let totals   = { cat => sum { val(row) | row in pipeline.records,
 3947:                                            cat(row) != '', num(val(row)) != bot }
 3948:                  | cat in range(cat_col) }

 3950:   pre  cat in params /\ val in params     else 400
 3951:   pre  cat in pipeline.cols               else 400
 3952:   pre  val in pipeline.cols               else 400
 3953:   pre  totals != {}                        else 200 "No plottable data"
 3954:   post HTML::D3->render_pie_chart_snippet(slices) embedded in TT layout
 3955:        where slices = sort_desc { |s.value| | s in totals }

 3988: =head2 Filter operators and the quick-filter bar
 3989: 
 3990: Filters are expressed as C<f=col:op:val> query parameters and are applied
 3991: server-side after all joins.  Multiple C<f=> params are applied in order
 3992: (AND semantics).
 3993: 
 3994: The colon separator is split with a limit of 3, so values may themselves
 3995: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 3996: C<f=start_time:eq:14:30:00>).
 3997: 
 3998: B<Supported operators:>
 3999: 
 4000:   eq        case-insensitive string equality
 4001:   ne        case-insensitive string inequality
 4002:   contains  case-insensitive substring match
 4003:   starts    case-insensitive prefix match
 4004:   lt        numeric less-than
 4005:   le        numeric less-than-or-equal
 4006:   gt        numeric greater-than
 4007:   ge        numeric greater-than-or-equal
 4008:   empty     cell is undef or empty string (val ignored)
 4009:   notempty  cell is defined and non-empty (val ignored)
 4010: 
 4011: B<Quick-filter bar (table view):>
 4012: 
 4013: A filter row below the toolbar lets the user pick a column, operator, and
 4014: value and press "Apply filter" (or Enter) to add a condition without
 4015: opening any panel.  The current URL is updated with the new C<f=> param
 4016: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 4017: preserved automatically via the browser C<URL> API.
 4018: 
 4019: Active filter chips appear in the toolbar.  Each chip has an individual
 4020: x-button to remove just that condition.  The "x Clear filters" link
 4021: removes all C<f=> params at once.
 4022: 
 4023: B<Drill-down from pie chart:>
 4024: 
 4025: Clicking a pie slice or legend entry on C</pie> navigates to the table
 4026: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 4027: rows behind any slice without manually typing a filter.

 4029: =head1 COMMON PITFALLS
 4030: 
 4031: These are the most common mistakes when working with this controller.
 4032: 
 4033: =over 4
 4034: 
 4035: =item B<SQLite files must use the .sql extension, not .sqlite>
 4036: 
 4037: C<Database::Abstraction> (the data-reading library) probes for a file called
 4038: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 4039: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 4040: rename it to C<inventory.sql> or it will not appear in the file browser and
 4041: will return 404 when opened.
 4042: 
 4043: =item B<Filter values that contain a colon still work>
 4044: 
 4045: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 4046: if your value itself contains a colon (for example, a time like C<14:30:00>),
 4047: the filter still works because the C<col:op:val> spec is split on the B<first
 4048: two> colons only -- the rest of the string becomes the value.
 4049: 
 4050:   # This correctly matches "14:30:00" in the start_time column:
 4051:   ?f=start_time:eq:14:30:00
 4052: 
 4053: =item B<Left join keeps only the FIRST matching right-table row>
 4054: 
 4055: When the right table has two rows with the same join key, only the first one
 4056: (in file order) is used.  The second is silently ignored.  If you need all
 4057: matches, consider pre-processing your data so join keys are unique.
 4058: 
 4059: =item B<Export format comes from the filename extension, not a Content-Type header>
 4060: 
 4061: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 4062: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 4063: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 4064: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 4065: ignored entirely.
 4066: 
 4067: =item B<Template Toolkit variables starting with underscore are silently dropped>
 4068: 
 4069: If you add a stash variable with a name starting with C<_> (for example,
 4070: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 4071: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 4072: is active.  Always use names that start with a letter.
 4073: 
 4074: =item B<_apply_filter_spec always passes all records through for unknown operators>
 4075: 
 4076: If you pass an operator that is not in the supported list (for example C<regex>
 4077: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 4078: error is produced.  This is intentional so that future operators can be added
 4079: without breaking existing clients that read a wider response.
 4080: 
 4081: =item B<Uploaded files are evicted automatically, but not immediately>
 4082: 
 4083: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 4084: application home directory.  C<Database::BI> evicts upload subdirectories
 4085: whose modification time is older than 24 hours B<on every server startup>.
 4086: Between restarts, files accumulate.  For an immediate full purge (regardless
 4087: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 4088: button in the UI.
 4089: 
 4090: =item B<Open C<data/> tables by name; open other files by absolute path>
 4091: 
 4092: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 4093: To open a file from anywhere else on the filesystem, use C<open_file>
 4094: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 4095: are not interchangeable.
 4096: 
 4097: =back
