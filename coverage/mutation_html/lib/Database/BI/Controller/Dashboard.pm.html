 1667: =head2 Filter operators
 1668: 
 1669: The C<f=col:op:val> filter spec supports:
 1670: 
 1671:   eq        case-insensitive string equality
 1672:   ne        case-insensitive string inequality
 1673:   contains  case-insensitive substring match
 1674:   starts    case-insensitive prefix match
 1675:   lt        numeric less-than
 1676:   le        numeric less-than-or-equal
 1677:   gt        numeric greater-than
 1678:   ge        numeric greater-than-or-equal
 1679:   empty     cell is undef or empty string (val ignored)
 1680:   notempty  cell is defined and non-empty (val ignored)
 1681: 
 1682: The colon separator is split with a limit of 3, so values may themselves
 1683: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).

 1685: =head1 COMMON PITFALLS
 1686: 
 1687: These are the most common mistakes when working with this controller.
 1688: 
 1689: =over 4
 1690: 
 1691: =item B<SQLite files must use the .sql extension, not .sqlite>
 1692: 
 1693: C<Database::Abstraction> (the data-reading library) probes for a file called
 1694: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1695: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1696: rename it to C<inventory.sql> or it will not appear in the file browser and
 1697: will return 404 when opened.
 1698: 
 1699: =item B<Filter values that contain a colon still work>
 1700: 
 1701: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1702: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1703: the filter still works because the C<col:op:val> spec is split on the B<first
 1704: two> colons only -- the rest of the string becomes the value.
 1705: 
 1706:   # This correctly matches "14:30:00" in the start_time column:
 1707:   ?f=start_time:eq:14:30:00
 1708: 
 1709: =item B<Left join keeps only the FIRST matching right-table row>
 1710: 
 1711: When the right table has two rows with the same join key, only the first one
 1712: (in file order) is used.  The second is silently ignored.  If you need all
 1713: matches, consider pre-processing your data so join keys are unique.
 1714: 
 1715: =item B<Export format comes from the filename extension, not a Content-Type header>
 1716: 
 1717: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1718: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1719: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1720: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1721: ignored entirely.
 1722: 
 1723: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1724: 
 1725: If you add a stash variable with a name starting with C<_> (for example,
 1726: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1727: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1728: is active.  Always use names that start with a letter.
 1729: 
 1730: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1731: 
 1732: If you pass an operator that is not in the supported list (for example C<regex>
 1733: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1734: error is produced.  This is intentional so that future operators can be added
 1735: without breaking existing clients that read a wider response.
 1736: 
 1737: =item B<Uploading a file does not clean up automatically>
 1738: 
 1739: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1740: application's home directory and are B<never deleted automatically>.  They
 1741: accumulate until you manually remove the C<.uploads/> directory.  This is
 1742: intentional for a single-user local tool, but you should be aware of it on
 1743: long-running servers.
 1744: 
 1745: =item B<Open C<data/> tables by name; open other files by absolute path>
 1746: 
 1747: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1748: To open a file from anywhere else on the filesystem, use C<open_file>
 1749: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1750: are not interchangeable.
