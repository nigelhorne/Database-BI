 1588: =head2 Filter operators
 1589: 
 1590: The C<f=col:op:val> filter spec supports:
 1591: 
 1592:   eq        case-insensitive string equality
 1593:   ne        case-insensitive string inequality
 1594:   contains  case-insensitive substring match
 1595:   starts    case-insensitive prefix match
 1596:   lt        numeric less-than
 1597:   le        numeric less-than-or-equal
 1598:   gt        numeric greater-than
 1599:   ge        numeric greater-than-or-equal
 1600:   empty     cell is undef or empty string (val ignored)
 1601:   notempty  cell is defined and non-empty (val ignored)
 1602: 
 1603: The colon separator is split with a limit of 3, so values may themselves
 1604: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1605: 
 1606: =head1 COMMON PITFALLS
 1607: 
 1608: These are the most common mistakes when working with this controller.
 1609: 
 1610: =over 4
 1611: 
 1612: =item B<SQLite files must use the .sql extension, not .sqlite>
 1613: 
 1614: C<Database::Abstraction> (the data-reading library) probes for a file called
 1615: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1616: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1617: rename it to C<inventory.sql> or it will not appear in the file browser and
 1618: will return 404 when opened.
 1619: 
 1620: =item B<Filter values that contain a colon still work>
 1621: 
 1622: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1623: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1624: the filter still works because the C<col:op:val> spec is split on the B<first
 1625: two> colons only -- the rest of the string becomes the value.
 1626: 
 1627:   # This correctly matches "14:30:00" in the start_time column:
 1628:   ?f=start_time:eq:14:30:00
 1629: 
 1630: =item B<Left join keeps only the FIRST matching right-table row>
 1631: 
 1632: When the right table has two rows with the same join key, only the first one
 1633: (in file order) is used.  The second is silently ignored.  If you need all
 1634: matches, consider pre-processing your data so join keys are unique.
 1635: 
 1636: =item B<Export format comes from the filename extension, not a Content-Type header>
 1637: 
 1638: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1639: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1640: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1641: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1642: ignored entirely.
 1643: 
 1644: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1645: 
 1646: If you add a stash variable with a name starting with C<_> (for example,
 1647: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1648: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1649: is active.  Always use names that start with a letter.
 1650: 
 1651: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1652: 
 1653: If you pass an operator that is not in the supported list (for example C<regex>
 1654: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1655: error is produced.  This is intentional so that future operators can be added
 1656: without breaking existing clients that read a wider response.
 1657: 
 1658: =item B<Uploading a file does not clean up automatically>
 1659: 
 1660: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1661: application's home directory and are B<never deleted automatically>.  They
 1662: accumulate until you manually remove the C<.uploads/> directory.  This is
 1663: intentional for a single-user local tool, but you should be aware of it on
 1664: long-running servers.
 1665: 
 1666: =item B<Open C<data/> tables by name; open other files by absolute path>
 1667: 
 1668: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1669: To open a file from anywhere else on the filesystem, use C<open_file>
 1670: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1671: are not interchangeable.
