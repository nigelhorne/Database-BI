 2385: an C<f=cat:eq:value> filter applied automatically, so the user can drill

 2495: =head2 Filter operators and the quick-filter bar
 2496: 
 2497: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2498: server-side after all joins.  Multiple C<f=> params are applied in order
 2499: (AND semantics).
 2500: 
 2501: The colon separator is split with a limit of 3, so values may themselves
 2502: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2503: C<f=start_time:eq:14:30:00>).
 2504: 
 2505: B<Supported operators:>
 2506: 
 2507:   eq        case-insensitive string equality
 2508:   ne        case-insensitive string inequality
 2509:   contains  case-insensitive substring match
 2510:   starts    case-insensitive prefix match
 2511:   lt        numeric less-than
 2512:   le        numeric less-than-or-equal
 2513:   gt        numeric greater-than
 2514:   ge        numeric greater-than-or-equal
 2515:   empty     cell is undef or empty string (val ignored)
 2516:   notempty  cell is defined and non-empty (val ignored)
 2517: 
 2518: B<Quick-filter bar (table view):>
 2519: 
 2520: A filter row below the toolbar lets the user pick a column, operator, and
 2521: value and press "Apply filter" (or Enter) to add a condition without
 2522: opening any panel.  The current URL is updated with the new C<f=> param
 2523: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2524: preserved automatically via the browser C<URL> API.
 2525: 
 2526: Active filter chips appear in the toolbar.  Each chip has an individual
 2527: x-button to remove just that condition.  The "x Clear filters" link
 2528: removes all C<f=> params at once.
 2529: 
 2530: B<Drill-down from pie chart:>
 2531: 
 2532: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2533: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2534: rows behind any slice without manually typing a filter.

 2536: =head1 COMMON PITFALLS
 2537: 
 2538: These are the most common mistakes when working with this controller.
 2539: 
 2540: =over 4
 2541: 
 2542: =item B<SQLite files must use the .sql extension, not .sqlite>
 2543: 
 2544: C<Database::Abstraction> (the data-reading library) probes for a file called
 2545: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2546: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2547: rename it to C<inventory.sql> or it will not appear in the file browser and
 2548: will return 404 when opened.
 2549: 
 2550: =item B<Filter values that contain a colon still work>
 2551: 
 2552: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2553: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2554: the filter still works because the C<col:op:val> spec is split on the B<first
 2555: two> colons only -- the rest of the string becomes the value.
 2556: 
 2557:   # This correctly matches "14:30:00" in the start_time column:
 2558:   ?f=start_time:eq:14:30:00
 2559: 
 2560: =item B<Left join keeps only the FIRST matching right-table row>
 2561: 
 2562: When the right table has two rows with the same join key, only the first one
 2563: (in file order) is used.  The second is silently ignored.  If you need all
 2564: matches, consider pre-processing your data so join keys are unique.
 2565: 
 2566: =item B<Export format comes from the filename extension, not a Content-Type header>
 2567: 
 2568: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2569: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2570: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2571: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2572: ignored entirely.
 2573: 
 2574: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2575: 
 2576: If you add a stash variable with a name starting with C<_> (for example,
 2577: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2578: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2579: is active.  Always use names that start with a letter.
 2580: 
 2581: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2582: 
 2583: If you pass an operator that is not in the supported list (for example C<regex>
 2584: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2585: error is produced.  This is intentional so that future operators can be added
 2586: without breaking existing clients that read a wider response.
 2587: 
 2588: =item B<Uploaded files are evicted automatically, but not immediately>
 2589: 
 2590: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2591: application home directory.  C<Database::BI> evicts upload subdirectories
 2592: whose modification time is older than 24 hours B<on every server startup>.
 2593: Between restarts, files accumulate.  For an immediate full purge (regardless
 2594: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2595: button in the UI.
 2596: 
 2597: =item B<Open C<data/> tables by name; open other files by absolute path>
 2598: 
 2599: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2600: To open a file from anywhere else on the filesystem, use C<open_file>
 2601: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2602: are not interchangeable.
 2603:
