 2730: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2731: C<f=start_time:eq:14:30:00>).
 2732: 
 2733: B<Supported operators:>
 2734: 
 2735:   eq        case-insensitive string equality
 2736:   ne        case-insensitive string inequality
 2737:   contains  case-insensitive substring match
 2738:   starts    case-insensitive prefix match
 2739:   lt        numeric less-than
 2740:   le        numeric less-than-or-equal
 2741:   gt        numeric greater-than
 2742:   ge        numeric greater-than-or-equal
 2743:   empty     cell is undef or empty string (val ignored)
 2744:   notempty  cell is defined and non-empty (val ignored)
 2745: 
 2746: B<Quick-filter bar (table view):>
 2747: 
 2748: A filter row below the toolbar lets the user pick a column, operator, and
 2749: value and press "Apply filter" (or Enter) to add a condition without
 2750: opening any panel.  The current URL is updated with the new C<f=> param
 2751: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2752: preserved automatically via the browser C<URL> API.
 2753: 
 2754: Active filter chips appear in the toolbar.  Each chip has an individual
 2755: x-button to remove just that condition.  The "x Clear filters" link
 2756: removes all C<f=> params at once.
 2757: 
 2758: B<Drill-down from pie chart:>
 2759: 
 2760: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2761: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2762: rows behind any slice without manually typing a filter.

 2764: =head1 COMMON PITFALLS
 2765: 
 2766: These are the most common mistakes when working with this controller.
 2767: 
 2768: =over 4
 2769: 
 2770: =item B<SQLite files must use the .sql extension, not .sqlite>
 2771: 
 2772: C<Database::Abstraction> (the data-reading library) probes for a file called
 2773: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2774: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2775: rename it to C<inventory.sql> or it will not appear in the file browser and
 2776: will return 404 when opened.
 2777: 
 2778: =item B<Filter values that contain a colon still work>
 2779: 
 2780: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2781: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2782: the filter still works because the C<col:op:val> spec is split on the B<first
 2783: two> colons only -- the rest of the string becomes the value.
 2784: 
 2785:   # This correctly matches "14:30:00" in the start_time column:
 2786:   ?f=start_time:eq:14:30:00
 2787: 
 2788: =item B<Left join keeps only the FIRST matching right-table row>
 2789: 
 2790: When the right table has two rows with the same join key, only the first one
 2791: (in file order) is used.  The second is silently ignored.  If you need all
 2792: matches, consider pre-processing your data so join keys are unique.
 2793: 
 2794: =item B<Export format comes from the filename extension, not a Content-Type header>
 2795: 
 2796: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2797: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2798: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2799: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2800: ignored entirely.
 2801: 
 2802: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2803: 
 2804: If you add a stash variable with a name starting with C<_> (for example,
 2805: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2806: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2807: is active.  Always use names that start with a letter.
 2808: 
 2809: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2810: 
 2811: If you pass an operator that is not in the supported list (for example C<regex>
 2812: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2813: error is produced.  This is intentional so that future operators can be added
 2814: without breaking existing clients that read a wider response.
 2815: 
 2816: =item B<Uploaded files are evicted automatically, but not immediately>
 2817: 
 2818: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2819: application home directory.  C<Database::BI> evicts upload subdirectories
 2820: whose modification time is older than 24 hours B<on every server startup>.
 2821: Between restarts, files accumulate.  For an immediate full purge (regardless
 2822: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2823: button in the UI.
 2824: 
 2825: =item B<Open C<data/> tables by name; open other files by absolute path>
 2826: 
 2827: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2828: To open a file from anywhere else on the filesystem, use C<open_file>
 2829: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2830: are not interchangeable.
 2831: 
 2832: =back

 2834: =head1 LIMITATIONS
 2835: 
 2836: =over 4
 2837: 
 2838: =item *
 2839: 
 2840: Multi-table joins are delegated to C<Database::Join> with C<backend =E<gt> 'auto'>.
 2841: For datasets up to C<join_max_rows> combined rows (default 10,000; configurable
 2842: in C<database_bi.conf>) the join runs in Perl memory; larger datasets spill to
 2843: a temporary SQLite database so peak RAM is bounded by the result set rather than
 2844: the sum of all source tables.

 2849: C<Accept-Language> tag (e.g. C<de> from C<de-DE,de;q=0.9,en;q=0.8>).
 2850: Quality weights and multiple alternatives are not ranked.
