 1532: =head2 Filter operators
 1533: 
 1534: The C<f=col:op:val> filter spec supports:
 1535: 
 1536:   eq        case-insensitive string equality
 1537:   ne        case-insensitive string inequality
 1538:   contains  case-insensitive substring match
 1539:   starts    case-insensitive prefix match
 1540:   lt        numeric less-than
 1541:   le        numeric less-than-or-equal
 1542:   gt        numeric greater-than
 1543:   ge        numeric greater-than-or-equal
 1544:   empty     cell is undef or empty string (val ignored)
 1545:   notempty  cell is defined and non-empty (val ignored)
 1546: 
 1547: The colon separator is split with a limit of 3, so values may themselves
 1548: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1549: 
 1550: =head1 COMMON PITFALLS
 1551: 
 1552: These are the most common mistakes when working with this controller.
 1553: 
 1554: =over 4
 1555: 
 1556: =item B<SQLite files must use the .sql extension, not .sqlite>
 1557: 
 1558: C<Database::Abstraction> (the data-reading library) probes for a file called
 1559: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1560: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1561: rename it to C<inventory.sql> or it will not appear in the file browser and
 1562: will return 404 when opened.
 1563: 
 1564: =item B<Filter values that contain a colon still work>
 1565: 
 1566: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1567: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1568: the filter still works because the C<col:op:val> spec is split on the B<first
 1569: two> colons only -- the rest of the string becomes the value.
 1570: 
 1571:   # This correctly matches "14:30:00" in the start_time column:
 1572:   ?f=start_time:eq:14:30:00
 1573: 
 1574: =item B<Left join keeps only the FIRST matching right-table row>
 1575: 
 1576: When the right table has two rows with the same join key, only the first one
 1577: (in file order) is used.  The second is silently ignored.  If you need all
 1578: matches, consider pre-processing your data so join keys are unique.
 1579: 
 1580: =item B<Export format comes from the filename extension, not a Content-Type header>
 1581: 
 1582: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1583: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1584: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1585: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1586: ignored entirely.
 1587: 
 1588: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1589: 
 1590: If you add a stash variable with a name starting with C<_> (for example,
 1591: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1592: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1593: is active.  Always use names that start with a letter.
 1594: 
 1595: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1596: 
 1597: If you pass an operator that is not in the supported list (for example C<regex>
 1598: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1599: error is produced.  This is intentional so that future operators can be added
 1600: without breaking existing clients that read a wider response.
 1601: 
 1602: =item B<Uploading a file does not clean up automatically>
 1603: 
 1604: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1605: application's home directory and are B<never deleted automatically>.  They
 1606: accumulate until you manually remove the C<.uploads/> directory.  This is
 1607: intentional for a single-user local tool, but you should be aware of it on
 1608: long-running servers.
 1609: 
 1610: =item B<Open C<data/> tables by name; open other files by absolute path>
 1611: 
 1612: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1613: To open a file from anywhere else on the filesystem, use C<open_file>
 1614: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1615: are not interchangeable.
 1616: 
 1617: =back
