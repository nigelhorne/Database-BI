 4913: 
 4914: C<GET /pie> -- Render a D3.js v7 animated pie chart from the current data

 4916:

 5034: =head2 Filter operators and the quick-filter bar
 5035: 
 5036: Filters are expressed as C<f=col:op:val> query parameters and are applied
 5037: server-side after all joins.  Multiple C<f=> params are applied in order
 5038: (AND semantics).
 5039: 
 5040: The colon separator is split with a limit of 3, so values may themselves
 5041: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 5042: C<f=start_time:eq:14:30:00>).
 5043: 
 5044: B<Supported operators:>
 5045: 
 5046:   eq        case-insensitive string equality
 5047:   ne        case-insensitive string inequality
 5048:   contains  case-insensitive substring match
 5049:   starts    case-insensitive prefix match
 5050:   lt        numeric less-than
 5051:   le        numeric less-than-or-equal
 5052:   gt        numeric greater-than
 5053:   ge        numeric greater-than-or-equal
 5054:   empty     cell is undef or empty string (val ignored)
 5055:   notempty  cell is defined and non-empty (val ignored)
 5056: 
 5057: B<Quick-filter bar (table view):>
 5058: 
 5059: A filter row below the toolbar lets the user pick a column, operator, and
 5060: value and press "Apply filter" (or Enter) to add a condition without
 5061: opening any panel.  The current URL is updated with the new C<f=> param
 5062: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 5063: preserved automatically via the browser C<URL> API.
 5064: 
 5065: Active filter chips appear in the toolbar.  Each chip has an individual
 5066: x-button to remove just that condition.  The "x Clear filters" link
 5067: removes all C<f=> params at once.
 5068: 
 5069: B<Drill-down from pie chart:>
 5070: 
 5071: Clicking a pie slice or legend entry on C</pie> navigates to the table
 5072: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 5073: rows behind any slice without manually typing a filter.

 5075: =head1 COMMON PITFALLS
 5076: 
 5077: These are the most common mistakes when working with this controller.
 5078: 
 5079: =over 4
 5080: 
 5081: =item B<SQLite files must use the .sql extension, not .sqlite>
 5082: 
 5083: C<Database::Abstraction> (the data-reading library) probes for a file called
 5084: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 5085: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 5086: rename it to C<inventory.sql> or it will not appear in the file browser and
 5087: will return 404 when opened.
 5088: 
 5089: =item B<Filter values that contain a colon still work>
 5090: 
 5091: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 5092: if your value itself contains a colon (for example, a time like C<14:30:00>),
 5093: the filter still works because the C<col:op:val> spec is split on the B<first
 5094: two> colons only -- the rest of the string becomes the value.
 5095: 
 5096:   # This correctly matches "14:30:00" in the start_time column:
 5097:   ?f=start_time:eq:14:30:00
 5098: 
 5099: =item B<Left join keeps only the FIRST matching right-table row>
 5100: 
 5101: When the right table has two rows with the same join key, only the first one
 5102: (in file order) is used.  The second is silently ignored.  If you need all
 5103: matches, consider pre-processing your data so join keys are unique.
 5104: 
 5105: =item B<Export format comes from the filename extension, not a Content-Type header>
 5106: 
 5107: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 5108: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 5109: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 5110: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 5111: ignored entirely.
 5112: 
 5113: =item B<Template Toolkit variables starting with underscore are silently dropped>
 5114: 
 5115: If you add a stash variable with a name starting with C<_> (for example,
 5116: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 5117: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 5118: is active.  Always use names that start with a letter.
 5119: 
 5120: =item B<_apply_filter_spec always passes all records through for unknown operators>
 5121: 
 5122: If you pass an operator that is not in the supported list (for example C<regex>
 5123: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 5124: error is produced.  This is intentional so that future operators can be added
 5125: without breaking existing clients that read a wider response.
 5126: 
 5127: =item B<Uploaded files are evicted automatically, but not immediately>
 5128: 
 5129: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 5130: application home directory.  C<Database::BI> evicts upload subdirectories
 5131: whose modification time is older than 24 hours B<on every server startup>.
 5132: Between restarts, files accumulate.  For an immediate full purge (regardless
 5133: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 5134: button in the UI.
 5135: 
 5136: =item B<Open C<data/> tables by name; open other files by absolute path>
 5137: 
 5138: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 5139: To open a file from anywhere else on the filesystem, use C<open_file>
 5140: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 5141: are not interchangeable.
 5142:
