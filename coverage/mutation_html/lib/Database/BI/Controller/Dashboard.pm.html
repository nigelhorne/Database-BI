 4383: =head2 Filter operators and the quick-filter bar
 4384: 
 4385: Filters are expressed as C<f=col:op:val> query parameters and are applied
 4386: server-side after all joins.  Multiple C<f=> params are applied in order
 4387: (AND semantics).
 4388: 
 4389: The colon separator is split with a limit of 3, so values may themselves
 4390: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 4391: C<f=start_time:eq:14:30:00>).
 4392: 
 4393: B<Supported operators:>
 4394: 
 4395:   eq        case-insensitive string equality
 4396:   ne        case-insensitive string inequality
 4397:   contains  case-insensitive substring match
 4398:   starts    case-insensitive prefix match
 4399:   lt        numeric less-than
 4400:   le        numeric less-than-or-equal
 4401:   gt        numeric greater-than
 4402:   ge        numeric greater-than-or-equal
 4403:   empty     cell is undef or empty string (val ignored)
 4404:   notempty  cell is defined and non-empty (val ignored)
 4405: 
 4406: B<Quick-filter bar (table view):>
 4407: 
 4408: A filter row below the toolbar lets the user pick a column, operator, and
 4409: value and press "Apply filter" (or Enter) to add a condition without
 4410: opening any panel.  The current URL is updated with the new C<f=> param
 4411: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 4412: preserved automatically via the browser C<URL> API.
 4413: 
 4414: Active filter chips appear in the toolbar.  Each chip has an individual
 4415: x-button to remove just that condition.  The "x Clear filters" link
 4416: removes all C<f=> params at once.
 4417: 
 4418: B<Drill-down from pie chart:>
 4419: 
 4420: Clicking a pie slice or legend entry on C</pie> navigates to the table
 4421: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 4422: rows behind any slice without manually typing a filter.

 4424: =head1 COMMON PITFALLS
 4425: 
 4426: These are the most common mistakes when working with this controller.
 4427: 
 4428: =over 4
 4429: 
 4430: =item B<SQLite files must use the .sql extension, not .sqlite>
 4431: 
 4432: C<Database::Abstraction> (the data-reading library) probes for a file called
 4433: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 4434: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 4435: rename it to C<inventory.sql> or it will not appear in the file browser and
 4436: will return 404 when opened.
 4437: 
 4438: =item B<Filter values that contain a colon still work>
 4439: 
 4440: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 4441: if your value itself contains a colon (for example, a time like C<14:30:00>),
 4442: the filter still works because the C<col:op:val> spec is split on the B<first
 4443: two> colons only -- the rest of the string becomes the value.
 4444: 
 4445:   # This correctly matches "14:30:00" in the start_time column:
 4446:   ?f=start_time:eq:14:30:00
 4447: 
 4448: =item B<Left join keeps only the FIRST matching right-table row>
 4449: 
 4450: When the right table has two rows with the same join key, only the first one
 4451: (in file order) is used.  The second is silently ignored.  If you need all
 4452: matches, consider pre-processing your data so join keys are unique.
 4453: 
 4454: =item B<Export format comes from the filename extension, not a Content-Type header>
 4455: 
 4456: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 4457: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 4458: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 4459: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 4460: ignored entirely.
 4461: 
 4462: =item B<Template Toolkit variables starting with underscore are silently dropped>
 4463: 
 4464: If you add a stash variable with a name starting with C<_> (for example,
 4465: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 4466: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 4467: is active.  Always use names that start with a letter.
 4468: 
 4469: =item B<_apply_filter_spec always passes all records through for unknown operators>
 4470: 
 4471: If you pass an operator that is not in the supported list (for example C<regex>
 4472: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 4473: error is produced.  This is intentional so that future operators can be added
 4474: without breaking existing clients that read a wider response.
 4475: 
 4476: =item B<Uploaded files are evicted automatically, but not immediately>
 4477: 
 4478: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 4479: application home directory.  C<Database::BI> evicts upload subdirectories
 4480: whose modification time is older than 24 hours B<on every server startup>.
 4481: Between restarts, files accumulate.  For an immediate full purge (regardless
 4482: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 4483: button in the UI.
 4484: 
 4485: =item B<Open C<data/> tables by name; open other files by absolute path>
 4486: 
 4487: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 4488: To open a file from anywhere else on the filesystem, use C<open_file>
 4489: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 4490: are not interchangeable.
