 1804: =head2 Filter operators
 1805: 
 1806: The C<f=col:op:val> filter spec supports:
 1807: 
 1808:   eq        case-insensitive string equality
 1809:   ne        case-insensitive string inequality
 1810:   contains  case-insensitive substring match
 1811:   starts    case-insensitive prefix match
 1812:   lt        numeric less-than
 1813:   le        numeric less-than-or-equal
 1814:   gt        numeric greater-than
 1815:   ge        numeric greater-than-or-equal
 1816:   empty     cell is undef or empty string (val ignored)
 1817:   notempty  cell is defined and non-empty (val ignored)
 1818: 
 1819: The colon separator is split with a limit of 3, so values may themselves
 1820: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1821: 
 1822: =head1 COMMON PITFALLS
 1823: 
 1824: These are the most common mistakes when working with this controller.
 1825: 
 1826: =over 4
 1827: 
 1828: =item B<SQLite files must use the .sql extension, not .sqlite>
 1829: 
 1830: C<Database::Abstraction> (the data-reading library) probes for a file called
 1831: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1832: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1833: rename it to C<inventory.sql> or it will not appear in the file browser and
 1834: will return 404 when opened.
 1835: 
 1836: =item B<Filter values that contain a colon still work>
 1837: 
 1838: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1839: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1840: the filter still works because the C<col:op:val> spec is split on the B<first
 1841: two> colons only -- the rest of the string becomes the value.
 1842: 
 1843:   # This correctly matches "14:30:00" in the start_time column:
 1844:   ?f=start_time:eq:14:30:00
 1845: 
 1846: =item B<Left join keeps only the FIRST matching right-table row>
 1847: 
 1848: When the right table has two rows with the same join key, only the first one
 1849: (in file order) is used.  The second is silently ignored.  If you need all
 1850: matches, consider pre-processing your data so join keys are unique.
 1851: 
 1852: =item B<Export format comes from the filename extension, not a Content-Type header>
 1853: 
 1854: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1855: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1856: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1857: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1858: ignored entirely.
 1859: 
 1860: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1861: 
 1862: If you add a stash variable with a name starting with C<_> (for example,
 1863: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1864: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1865: is active.  Always use names that start with a letter.
 1866: 
 1867: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1868: 
 1869: If you pass an operator that is not in the supported list (for example C<regex>
 1870: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1871: error is produced.  This is intentional so that future operators can be added
 1872: without breaking existing clients that read a wider response.
 1873: 
 1874: =item B<Uploading a file does not clean up automatically>
 1875: 
 1876: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1877: application's home directory and are B<never deleted automatically>.  They
 1878: accumulate until you manually remove the C<.uploads/> directory.  This is
 1879: intentional for a single-user local tool, but you should be aware of it on
 1880: long-running servers.
 1881: 
 1882: =item B<Open C<data/> tables by name; open other files by absolute path>
 1883: 
 1884: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1885: To open a file from anywhere else on the filesystem, use C<open_file>
 1886: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1887: are not interchangeable.
