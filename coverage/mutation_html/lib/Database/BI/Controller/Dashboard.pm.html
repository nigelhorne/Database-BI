 2293: =head1 COMMON PITFALLS
 2294: 
 2295: These are the most common mistakes when working with this controller.
 2296: 
 2297: =over 4
 2298: 
 2299: =item B<SQLite files must use the .sql extension, not .sqlite>
 2300: 
 2301: C<Database::Abstraction> (the data-reading library) probes for a file called
 2302: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2303: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2304: rename it to C<inventory.sql> or it will not appear in the file browser and
 2305: will return 404 when opened.
 2306: 
 2307: =item B<Filter values that contain a colon still work>
 2308: 
 2309: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2310: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2311: the filter still works because the C<col:op:val> spec is split on the B<first
 2312: two> colons only -- the rest of the string becomes the value.
 2313: 
 2314:   # This correctly matches "14:30:00" in the start_time column:
 2315:   ?f=start_time:eq:14:30:00
 2316: 
 2317: =item B<Left join keeps only the FIRST matching right-table row>
 2318: 
 2319: When the right table has two rows with the same join key, only the first one
 2320: (in file order) is used.  The second is silently ignored.  If you need all
 2321: matches, consider pre-processing your data so join keys are unique.
 2322: 
 2323: =item B<Export format comes from the filename extension, not a Content-Type header>
 2324: 
 2325: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2326: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2327: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2328: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2329: ignored entirely.
 2330: 
 2331: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2332: 
 2333: If you add a stash variable with a name starting with C<_> (for example,
 2334: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2335: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2336: is active.  Always use names that start with a letter.
 2337: 
 2338: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2339: 
 2340: If you pass an operator that is not in the supported list (for example C<regex>
 2341: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2342: error is produced.  This is intentional so that future operators can be added
 2343: without breaking existing clients that read a wider response.
 2344: 
 2345: =item B<Uploading a file does not clean up automatically>
 2346: 
 2347: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2348: application's home directory and are B<never deleted automatically>.  They
 2349: accumulate until you manually remove the C<.uploads/> directory.  This is
 2350: intentional for a single-user local tool, but you should be aware of it on
 2351: long-running servers.
 2352: 
 2353: =item B<Open C<data/> tables by name; open other files by absolute path>
 2354: 
 2355: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2356: To open a file from anywhere else on the filesystem, use C<open_file>
 2357: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2358: are not interchangeable.
