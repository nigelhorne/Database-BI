 2491: =head2 Filter operators and the quick-filter bar
 2492: 
 2493: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2494: server-side after all joins.  Multiple C<f=> params are applied in order
 2495: (AND semantics).
 2496: 
 2497: The colon separator is split with a limit of 3, so values may themselves
 2498: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2499: C<f=start_time:eq:14:30:00>).
 2500: 
 2501: B<Supported operators:>
 2502: 
 2503:   eq        case-insensitive string equality
 2504:   ne        case-insensitive string inequality
 2505:   contains  case-insensitive substring match
 2506:   starts    case-insensitive prefix match
 2507:   lt        numeric less-than
 2508:   le        numeric less-than-or-equal
 2509:   gt        numeric greater-than
 2510:   ge        numeric greater-than-or-equal
 2511:   empty     cell is undef or empty string (val ignored)
 2512:   notempty  cell is defined and non-empty (val ignored)
 2513: 
 2514: B<Quick-filter bar (table view):>
 2515: 
 2516: A filter row below the toolbar lets the user pick a column, operator, and
 2517: value and press "Apply filter" (or Enter) to add a condition without
 2518: opening any panel.  The current URL is updated with the new C<f=> param
 2519: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2520: preserved automatically via the browser C<URL> API.
 2521: 
 2522: Active filter chips appear in the toolbar.  Each chip has an individual
 2523: x-button to remove just that condition.  The "x Clear filters" link
 2524: removes all C<f=> params at once.
 2525: 
 2526: B<Drill-down from pie chart:>
 2527: 
 2528: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2529: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2530: rows behind any slice without manually typing a filter.

 2532: =head1 COMMON PITFALLS
 2533: 
 2534: These are the most common mistakes when working with this controller.
 2535: 
 2536: =over 4
 2537: 
 2538: =item B<SQLite files must use the .sql extension, not .sqlite>
 2539: 
 2540: C<Database::Abstraction> (the data-reading library) probes for a file called
 2541: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2542: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2543: rename it to C<inventory.sql> or it will not appear in the file browser and
 2544: will return 404 when opened.
 2545: 
 2546: =item B<Filter values that contain a colon still work>
 2547: 
 2548: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2549: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2550: the filter still works because the C<col:op:val> spec is split on the B<first
 2551: two> colons only -- the rest of the string becomes the value.
 2552: 
 2553:   # This correctly matches "14:30:00" in the start_time column:
 2554:   ?f=start_time:eq:14:30:00
 2555: 
 2556: =item B<Left join keeps only the FIRST matching right-table row>
 2557: 
 2558: When the right table has two rows with the same join key, only the first one
 2559: (in file order) is used.  The second is silently ignored.  If you need all
 2560: matches, consider pre-processing your data so join keys are unique.
 2561: 
 2562: =item B<Export format comes from the filename extension, not a Content-Type header>
 2563: 
 2564: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2565: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2566: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2567: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2568: ignored entirely.
 2569: 
 2570: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2571: 
 2572: If you add a stash variable with a name starting with C<_> (for example,
 2573: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2574: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2575: is active.  Always use names that start with a letter.
 2576: 
 2577: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2578: 
 2579: If you pass an operator that is not in the supported list (for example C<regex>
 2580: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2581: error is produced.  This is intentional so that future operators can be added
 2582: without breaking existing clients that read a wider response.
 2583: 
 2584: =item B<Uploaded files are evicted automatically, but not immediately>
 2585: 
 2586: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2587: application home directory.  C<Database::BI> evicts upload subdirectories
 2588: whose modification time is older than 24 hours B<on every server startup>.
 2589: Between restarts, files accumulate.  For an immediate full purge (regardless
 2590: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2591: button in the UI.
 2592: 
 2593: =item B<Open C<data/> tables by name; open other files by absolute path>
 2594: 
 2595: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2596: To open a file from anywhere else on the filesystem, use C<open_file>
 2597: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2598: are not interchangeable.
