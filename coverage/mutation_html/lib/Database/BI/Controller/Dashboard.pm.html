 2399:           currency symbols, commas, and handling accounting-notation negatives).
 2400:           Rows where the value is still non-numeric after stripping are skipped.
 2401:           Negative totals are included in the chart (slice values may be negative
 2402:           if the source data contains credits or reversals).
 2403: 
 2404:   donut=  Any truthy value (e.g. "1") enables the donut hole.  Absent or
 2405:           "0" renders a solid pie.
 2406:

 2408: 
 2409:   Missing cat or val column parameter    C<cat=> or C<val=> query param absent.
 2410:   Column not found: <name>               Named column absent from the result set.
 2411:   Could not open data source             Left-table spec unresolvable or 404.

 2415:

 2472: =head2 Filter operators and the quick-filter bar
 2473: 
 2474: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2475: server-side after all joins.  Multiple C<f=> params are applied in order
 2476: (AND semantics).
 2477: 
 2478: The colon separator is split with a limit of 3, so values may themselves
 2479: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2480: C<f=start_time:eq:14:30:00>).
 2481: 
 2482: B<Supported operators:>
 2483: 
 2484:   eq        case-insensitive string equality
 2485:   ne        case-insensitive string inequality
 2486:   contains  case-insensitive substring match
 2487:   starts    case-insensitive prefix match
 2488:   lt        numeric less-than
 2489:   le        numeric less-than-or-equal
 2490:   gt        numeric greater-than
 2491:   ge        numeric greater-than-or-equal
 2492:   empty     cell is undef or empty string (val ignored)
 2493:   notempty  cell is defined and non-empty (val ignored)
 2494: 
 2495: B<Quick-filter bar (table view):>
 2496: 
 2497: A filter row below the toolbar lets the user pick a column, operator, and
 2498: value and press "Apply filter" (or Enter) to add a condition without
 2499: opening any panel.  The current URL is updated with the new C<f=> param
 2500: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2501: preserved automatically via the browser C<URL> API.
 2502: 
 2503: Active filter chips appear in the toolbar.  Each chip has an individual
 2504: x-button to remove just that condition.  The "x Clear filters" link
 2505: removes all C<f=> params at once.
 2506: 
 2507: B<Drill-down from pie chart:>
 2508: 
 2509: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2510: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2511: rows behind any slice without manually typing a filter.

 2513: =head1 COMMON PITFALLS
 2514: 
 2515: These are the most common mistakes when working with this controller.
 2516: 
 2517: =over 4
 2518: 
 2519: =item B<SQLite files must use the .sql extension, not .sqlite>
 2520: 
 2521: C<Database::Abstraction> (the data-reading library) probes for a file called
 2522: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2523: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2524: rename it to C<inventory.sql> or it will not appear in the file browser and
 2525: will return 404 when opened.
 2526: 
 2527: =item B<Filter values that contain a colon still work>
 2528: 
 2529: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2530: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2531: the filter still works because the C<col:op:val> spec is split on the B<first
 2532: two> colons only -- the rest of the string becomes the value.
 2533: 
 2534:   # This correctly matches "14:30:00" in the start_time column:
 2535:   ?f=start_time:eq:14:30:00
 2536: 
 2537: =item B<Left join keeps only the FIRST matching right-table row>
 2538: 
 2539: When the right table has two rows with the same join key, only the first one
 2540: (in file order) is used.  The second is silently ignored.  If you need all
 2541: matches, consider pre-processing your data so join keys are unique.
 2542: 
 2543: =item B<Export format comes from the filename extension, not a Content-Type header>
 2544: 
 2545: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2546: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2547: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2548: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2549: ignored entirely.
 2550: 
 2551: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2552: 
 2553: If you add a stash variable with a name starting with C<_> (for example,
 2554: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2555: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2556: is active.  Always use names that start with a letter.
 2557: 
 2558: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2559: 
 2560: If you pass an operator that is not in the supported list (for example C<regex>
 2561: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2562: error is produced.  This is intentional so that future operators can be added
 2563: without breaking existing clients that read a wider response.
 2564: 
 2565: =item B<Uploaded files are evicted automatically, but not immediately>
 2566: 
 2567: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2568: application home directory.  C<Database::BI> evicts upload subdirectories
 2569: whose modification time is older than 24 hours B<on every server startup>.
 2570: Between restarts, files accumulate.  For an immediate full purge (regardless
 2571: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2572: button in the UI.
 2573: 
 2574: =item B<Open C<data/> tables by name; open other files by absolute path>
 2575: 
 2576: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2577: To open a file from anywhere else on the filesystem, use C<open_file>
 2578: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2579: are not interchangeable.
 2580: 
 2581: =back
