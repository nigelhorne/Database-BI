 1536: =head2 Filter operators
 1537: 
 1538: The C<f=col:op:val> filter spec supports:
 1539: 
 1540:   eq        case-insensitive string equality
 1541:   ne        case-insensitive string inequality
 1542:   contains  case-insensitive substring match
 1543:   starts    case-insensitive prefix match
 1544:   lt        numeric less-than
 1545:   le        numeric less-than-or-equal
 1546:   gt        numeric greater-than
 1547:   ge        numeric greater-than-or-equal
 1548:   empty     cell is undef or empty string (val ignored)
 1549:   notempty  cell is defined and non-empty (val ignored)
 1550: 
 1551: The colon separator is split with a limit of 3, so values may themselves
 1552: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1553: 
 1554: =head1 COMMON PITFALLS
 1555: 
 1556: These are the most common mistakes when working with this controller.
 1557: 
 1558: =over 4
 1559: 
 1560: =item B<SQLite files must use the .sql extension, not .sqlite>
 1561: 
 1562: C<Database::Abstraction> (the data-reading library) probes for a file called
 1563: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1564: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1565: rename it to C<inventory.sql> or it will not appear in the file browser and
 1566: will return 404 when opened.
 1567: 
 1568: =item B<Filter values that contain a colon still work>
 1569: 
 1570: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1571: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1572: the filter still works because the C<col:op:val> spec is split on the B<first
 1573: two> colons only -- the rest of the string becomes the value.
 1574: 
 1575:   # This correctly matches "14:30:00" in the start_time column:
 1576:   ?f=start_time:eq:14:30:00
 1577: 
 1578: =item B<Left join keeps only the FIRST matching right-table row>
 1579: 
 1580: When the right table has two rows with the same join key, only the first one
 1581: (in file order) is used.  The second is silently ignored.  If you need all
 1582: matches, consider pre-processing your data so join keys are unique.
 1583: 
 1584: =item B<Export format comes from the filename extension, not a Content-Type header>
 1585: 
 1586: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1587: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1588: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1589: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1590: ignored entirely.
 1591: 
 1592: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1593: 
 1594: If you add a stash variable with a name starting with C<_> (for example,
 1595: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1596: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1597: is active.  Always use names that start with a letter.
 1598: 
 1599: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1600: 
 1601: If you pass an operator that is not in the supported list (for example C<regex>
 1602: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1603: error is produced.  This is intentional so that future operators can be added
 1604: without breaking existing clients that read a wider response.
 1605: 
 1606: =item B<Uploading a file does not clean up automatically>
 1607: 
 1608: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1609: application's home directory and are B<never deleted automatically>.  They
 1610: accumulate until you manually remove the C<.uploads/> directory.  This is
 1611: intentional for a single-user local tool, but you should be aware of it on
 1612: long-running servers.
 1613: 
 1614: =item B<Open C<data/> tables by name; open other files by absolute path>
 1615: 
 1616: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1617: To open a file from anywhere else on the filesystem, use C<open_file>
 1618: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1619: are not interchangeable.
 1620: 
 1621: =back
