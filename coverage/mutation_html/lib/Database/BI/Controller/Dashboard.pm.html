 2337: =head1 COMMON PITFALLS
 2338: 
 2339: These are the most common mistakes when working with this controller.
 2340: 
 2341: =over 4
 2342: 
 2343: =item B<SQLite files must use the .sql extension, not .sqlite>
 2344: 
 2345: C<Database::Abstraction> (the data-reading library) probes for a file called
 2346: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2347: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2348: rename it to C<inventory.sql> or it will not appear in the file browser and
 2349: will return 404 when opened.
 2350: 
 2351: =item B<Filter values that contain a colon still work>
 2352: 
 2353: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2354: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2355: the filter still works because the C<col:op:val> spec is split on the B<first
 2356: two> colons only -- the rest of the string becomes the value.
 2357: 
 2358:   # This correctly matches "14:30:00" in the start_time column:
 2359:   ?f=start_time:eq:14:30:00
 2360: 
 2361: =item B<Left join keeps only the FIRST matching right-table row>
 2362: 
 2363: When the right table has two rows with the same join key, only the first one
 2364: (in file order) is used.  The second is silently ignored.  If you need all
 2365: matches, consider pre-processing your data so join keys are unique.
 2366: 
 2367: =item B<Export format comes from the filename extension, not a Content-Type header>
 2368: 
 2369: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2370: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2371: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2372: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2373: ignored entirely.
 2374: 
 2375: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2376: 
 2377: If you add a stash variable with a name starting with C<_> (for example,
 2378: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2379: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2380: is active.  Always use names that start with a letter.
 2381: 
 2382: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2383: 
 2384: If you pass an operator that is not in the supported list (for example C<regex>
 2385: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2386: error is produced.  This is intentional so that future operators can be added
 2387: without breaking existing clients that read a wider response.
 2388: 
 2389: =item B<Uploading a file does not clean up automatically>
 2390: 
 2391: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2392: application's home directory and are B<never deleted automatically>.  They
 2393: accumulate until you manually remove the C<.uploads/> directory.  This is
 2394: intentional for a single-user local tool, but you should be aware of it on
 2395: long-running servers.
 2396: 
 2397: =item B<Open C<data/> tables by name; open other files by absolute path>
 2398: 
 2399: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2400: To open a file from anywhere else on the filesystem, use C<open_file>
 2401: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2402: are not interchangeable.
