 2487: =head2 pie_view
 2488: 
 2489: C<GET /pie> -- Render a D3.js v7 animated pie chart from the current data
 2490: pipeline.
 2491: 
 2492: Each row's category value (C<cat=>) is used as a slice label; the numeric
 2493: value column (C<val=>) is summed per category.  Accounting-notation
 2494: negatives such as C<(1,234.56)> are handled automatically.  Slices are
 2495: sorted by total descending; when there are more than 12 distinct categories
 2496: the smallest ones are collapsed into a single "Other" slice.
 2497: 
 2498: Clicking any slice or legend entry navigates back to the table view with
 2499: an C<f=cat:eq:value> filter applied automatically, so the user can drill
 2500: into the data behind a slice without leaving the application.
 2501: 
 2502: =head3 API SPECIFICATION
 2503: 
 2504: =head4 INPUT
 2505: 
 2506:   l=<spec>    string   Left-table spec (required).  Same syntax as /join.
 2507:   cat=<col>   string   Category column name (required; used as slice labels).
 2508:   val=<col>   string   Numeric value column name (required; values are summed).
 2509:   donut=1     flag     Render as a donut chart with a hole in the centre (optional).
 2510:   back=<url>  string   URL for the "Back to table" breadcrumb link (optional; default "/").
 2511:   f=<spec>    string   Result filter (repeatable; same syntax as /join).
 2512: 
 2513: =head4 OUTPUT
 2514: 
 2515:   200 text/html   TT-rendered pie chart page containing:
 2516:                   - Two-level breadcrumb (Home > Back to table).
 2517:                   - Export buttons for SVG and PNG (legend is composited in).
 2518:                   - An animated D3.js pie or donut chart with a colour-coded
 2519:                     legend.  Each slice and legend entry is clickable and
 2520:                     navigates to the filtered table view.
 2521:                   - Slice count (e.g. "7 slices").
 2522: 
 2523:   200 text/plain  "No plottable data" when every row has a non-numeric or
 2524:                   missing value column (HTTP 200, not 4xx, so the page can
 2525:                   render a friendly message).
 2526: 
 2527:   400 text/plain  C<cat=> or C<val=> absent, or named column not found.
 2528:   404 text/plain  Data source could not be opened.
 2529: 
 2530: =head4 DOMAIN CONSTRAINTS
 2531: 
 2532:   cat=    Any column name that exists in the result set.  Cell values are
 2533:           used verbatim as slice labels.  Empty-string cells are skipped.
 2534: 
 2535:   val=    Must be a column whose cells contain numbers (after stripping
 2536:           currency symbols, commas, and handling accounting-notation negatives).

 2609: =head2 Filter operators and the quick-filter bar
 2610: 
 2611: Filters are expressed as C<f=col:op:val> query parameters and are applied
 2612: server-side after all joins.  Multiple C<f=> params are applied in order
 2613: (AND semantics).
 2614: 
 2615: The colon separator is split with a limit of 3, so values may themselves
 2616: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 2617: C<f=start_time:eq:14:30:00>).
 2618: 
 2619: B<Supported operators:>
 2620: 
 2621:   eq        case-insensitive string equality
 2622:   ne        case-insensitive string inequality
 2623:   contains  case-insensitive substring match
 2624:   starts    case-insensitive prefix match
 2625:   lt        numeric less-than
 2626:   le        numeric less-than-or-equal
 2627:   gt        numeric greater-than
 2628:   ge        numeric greater-than-or-equal
 2629:   empty     cell is undef or empty string (val ignored)
 2630:   notempty  cell is defined and non-empty (val ignored)
 2631: 
 2632: B<Quick-filter bar (table view):>
 2633: 
 2634: A filter row below the toolbar lets the user pick a column, operator, and
 2635: value and press "Apply filter" (or Enter) to add a condition without
 2636: opening any panel.  The current URL is updated with the new C<f=> param
 2637: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 2638: preserved automatically via the browser C<URL> API.
 2639: 
 2640: Active filter chips appear in the toolbar.  Each chip has an individual
 2641: x-button to remove just that condition.  The "x Clear filters" link
 2642: removes all C<f=> params at once.
 2643: 
 2644: B<Drill-down from pie chart:>
 2645: 
 2646: Clicking a pie slice or legend entry on C</pie> navigates to the table
 2647: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 2648: rows behind any slice without manually typing a filter.

 2650: =head1 COMMON PITFALLS
 2651: 
 2652: These are the most common mistakes when working with this controller.
 2653: 
 2654: =over 4
 2655: 
 2656: =item B<SQLite files must use the .sql extension, not .sqlite>
 2657: 
 2658: C<Database::Abstraction> (the data-reading library) probes for a file called
 2659: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2660: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2661: rename it to C<inventory.sql> or it will not appear in the file browser and
 2662: will return 404 when opened.
 2663: 
 2664: =item B<Filter values that contain a colon still work>
 2665: 
 2666: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2667: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2668: the filter still works because the C<col:op:val> spec is split on the B<first
 2669: two> colons only -- the rest of the string becomes the value.
 2670: 
 2671:   # This correctly matches "14:30:00" in the start_time column:
 2672:   ?f=start_time:eq:14:30:00
 2673: 
 2674: =item B<Left join keeps only the FIRST matching right-table row>
 2675: 
 2676: When the right table has two rows with the same join key, only the first one
 2677: (in file order) is used.  The second is silently ignored.  If you need all
 2678: matches, consider pre-processing your data so join keys are unique.
 2679: 
 2680: =item B<Export format comes from the filename extension, not a Content-Type header>
 2681: 
 2682: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2683: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2684: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2685: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2686: ignored entirely.
 2687: 
 2688: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2689: 
 2690: If you add a stash variable with a name starting with C<_> (for example,
 2691: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2692: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2693: is active.  Always use names that start with a letter.
 2694: 
 2695: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2696: 
 2697: If you pass an operator that is not in the supported list (for example C<regex>
 2698: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2699: error is produced.  This is intentional so that future operators can be added
 2700: without breaking existing clients that read a wider response.
 2701: 
 2702: =item B<Uploaded files are evicted automatically, but not immediately>
 2703: 
 2704: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2705: application home directory.  C<Database::BI> evicts upload subdirectories
 2706: whose modification time is older than 24 hours B<on every server startup>.
 2707: Between restarts, files accumulate.  For an immediate full purge (regardless
 2708: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 2709: button in the UI.
 2710: 
 2711: =item B<Open C<data/> tables by name; open other files by absolute path>
 2712: 
 2713: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2714: To open a file from anywhere else on the filesystem, use C<open_file>
 2715: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2716: are not interchangeable.
 2717: 
 2718: =back
