 1670: =head2 Filter operators
 1671: 
 1672: The C<f=col:op:val> filter spec supports:
 1673: 
 1674:   eq        case-insensitive string equality
 1675:   ne        case-insensitive string inequality
 1676:   contains  case-insensitive substring match
 1677:   starts    case-insensitive prefix match
 1678:   lt        numeric less-than
 1679:   le        numeric less-than-or-equal
 1680:   gt        numeric greater-than
 1681:   ge        numeric greater-than-or-equal
 1682:   empty     cell is undef or empty string (val ignored)
 1683:   notempty  cell is defined and non-empty (val ignored)
 1684: 
 1685: The colon separator is split with a limit of 3, so values may themselves
 1686: contain colons (e.g. C<f=sale_date:eq:2025-01-15>).
 1687: 
 1688: =head1 COMMON PITFALLS
 1689: 
 1690: These are the most common mistakes when working with this controller.
 1691: 
 1692: =over 4
 1693: 
 1694: =item B<SQLite files must use the .sql extension, not .sqlite>
 1695: 
 1696: C<Database::Abstraction> (the data-reading library) probes for a file called
 1697: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 1698: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 1699: rename it to C<inventory.sql> or it will not appear in the file browser and
 1700: will return 404 when opened.
 1701: 
 1702: =item B<Filter values that contain a colon still work>
 1703: 
 1704: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 1705: if your value itself contains a colon (for example, a time like C<14:30:00>),
 1706: the filter still works because the C<col:op:val> spec is split on the B<first
 1707: two> colons only -- the rest of the string becomes the value.
 1708: 
 1709:   # This correctly matches "14:30:00" in the start_time column:
 1710:   ?f=start_time:eq:14:30:00
 1711: 
 1712: =item B<Left join keeps only the FIRST matching right-table row>
 1713: 
 1714: When the right table has two rows with the same join key, only the first one
 1715: (in file order) is used.  The second is silently ignored.  If you need all
 1716: matches, consider pre-processing your data so join keys are unique.
 1717: 
 1718: =item B<Export format comes from the filename extension, not a Content-Type header>
 1719: 
 1720: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 1721: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 1722: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 1723: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 1724: ignored entirely.
 1725: 
 1726: =item B<Template Toolkit variables starting with underscore are silently dropped>
 1727: 
 1728: If you add a stash variable with a name starting with C<_> (for example,
 1729: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 1730: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 1731: is active.  Always use names that start with a letter.
 1732: 
 1733: =item B<_apply_filter_spec always passes all records through for unknown operators>
 1734: 
 1735: If you pass an operator that is not in the supported list (for example C<regex>
 1736: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 1737: error is produced.  This is intentional so that future operators can be added
 1738: without breaking existing clients that read a wider response.
 1739: 
 1740: =item B<Uploading a file does not clean up automatically>
 1741: 
 1742: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 1743: application's home directory and are B<never deleted automatically>.  They
 1744: accumulate until you manually remove the C<.uploads/> directory.  This is
 1745: intentional for a single-user local tool, but you should be aware of it on
 1746: long-running servers.
 1747: 
 1748: =item B<Open C<data/> tables by name; open other files by absolute path>
 1749: 
 1750: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 1751: To open a file from anywhere else on the filesystem, use C<open_file>
 1752: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 1753: are not interchangeable.
 1754:
