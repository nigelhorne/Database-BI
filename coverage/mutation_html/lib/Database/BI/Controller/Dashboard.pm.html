 3126: =head2 pie_view
 3127: 
 3128: C<GET /pie> -- Render a D3.js v7 animated pie chart from the current data
 3129: pipeline.
 3130: 
 3131: Each row's category value (C<cat=>) is used as a slice label; the numeric
 3132: value column (C<val=>) is summed per category.  Accounting-notation
 3133: negatives such as C<(1,234.56)> are handled automatically.  Slices are
 3134: sorted by total descending; when there are more than 12 distinct categories
 3135: the smallest ones are collapsed into a single "Other" slice.
 3136: 
 3137: Clicking any slice or legend entry navigates back to the table view with
 3138: an C<f=cat:eq:value> filter applied automatically, so the user can drill
 3139: into the data behind a slice without leaving the application.
 3140: 
 3141: =head3 API SPECIFICATION
 3142: 
 3143: =head4 INPUT
 3144: 
 3145:   l=<spec>    string   Left-table spec (required).  Same syntax as /join.
 3146:   cat=<col>   string   Category column name (required; used as slice labels).
 3147:   val=<col>   string   Numeric value column name (required; values are summed).
 3148:   donut=1     flag     Render as a donut chart with a hole in the centre (optional).
 3149:   back=<url>  string   URL for the "Back to table" breadcrumb link (optional; default "/").
 3150:   f=<spec>    string   Result filter (repeatable; same syntax as /join).
 3151: 
 3152: =head4 OUTPUT
 3153: 
 3154:   200 text/html   TT-rendered pie chart page containing:
 3155:                   - Two-level breadcrumb (Home > Back to table).
 3156:                   - Export buttons for SVG and PNG (legend is composited in).
 3157:                   - An animated D3.js pie or donut chart with a colour-coded
 3158:                     legend.  Each slice and legend entry is clickable and
 3159:                     navigates to the filtered table view.
 3160:                   - Slice count (e.g. "7 slices").
 3161: 
 3162:   200 text/plain  "No plottable data" when every row has a non-numeric or
 3163:                   missing value column (HTTP 200, not 4xx, so the page can
 3164:                   render a friendly message).
 3165: 
 3166:   400 text/plain  C<cat=> or C<val=> absent, or named column not found.
 3167:   404 text/plain  Data source could not be opened.
 3168: 
 3169: =head4 DOMAIN CONSTRAINTS
 3170: 
 3171:   cat=    Any column name that exists in the result set.  Cell values are
 3172:           used verbatim as slice labels.  Empty-string cells are skipped.
 3173: 
 3174:   val=    Must be a column whose cells contain numbers (after stripping
 3175:           currency symbols, commas, and handling accounting-notation negatives).
 3176:           Rows where the value is still non-numeric after stripping are skipped.
 3177:           Negative totals are included in the chart (slice values may be negative
 3178:           if the source data contains credits or reversals).
 3179: 
 3180:   donut=  Any truthy value (e.g. "1") enables the donut hole.  Absent or
 3181:           "0" renders a solid pie.
 3182:

 3184: 
 3185:   Missing cat or val column parameter    C<cat=> or C<val=> query param absent.
 3186:   Column not found: <name>               Named column absent from the result set.
 3187:   Could not open data source             Left-table spec unresolvable or 404.
 3188:   No plottable data: ...                 All rows lack a valid numeric value.

 3191: 
 3192:   GET /pie?l=table:sales&cat=region&val=amount&back=/view/sales
 3193:

 3196:

 3198: 
 3199:   GET /pie?l=table:sales&cat=region&val=amount&donut=1

 3248: =head2 Filter operators and the quick-filter bar
 3249: 
 3250: Filters are expressed as C<f=col:op:val> query parameters and are applied
 3251: server-side after all joins.  Multiple C<f=> params are applied in order
 3252: (AND semantics).
 3253: 
 3254: The colon separator is split with a limit of 3, so values may themselves
 3255: contain colons (e.g. C<f=sale_date:eq:2025-01-15>, or a time value like
 3256: C<f=start_time:eq:14:30:00>).
 3257: 
 3258: B<Supported operators:>
 3259: 
 3260:   eq        case-insensitive string equality
 3261:   ne        case-insensitive string inequality
 3262:   contains  case-insensitive substring match
 3263:   starts    case-insensitive prefix match
 3264:   lt        numeric less-than
 3265:   le        numeric less-than-or-equal
 3266:   gt        numeric greater-than
 3267:   ge        numeric greater-than-or-equal
 3268:   empty     cell is undef or empty string (val ignored)
 3269:   notempty  cell is defined and non-empty (val ignored)
 3270: 
 3271: B<Quick-filter bar (table view):>
 3272: 
 3273: A filter row below the toolbar lets the user pick a column, operator, and
 3274: value and press "Apply filter" (or Enter) to add a condition without
 3275: opening any panel.  The current URL is updated with the new C<f=> param
 3276: and the page reloads; all other URL parameters (joins, dedup, etc.) are
 3277: preserved automatically via the browser C<URL> API.
 3278: 
 3279: Active filter chips appear in the toolbar.  Each chip has an individual
 3280: x-button to remove just that condition.  The "x Clear filters" link
 3281: removes all C<f=> params at once.
 3282: 
 3283: B<Drill-down from pie chart:>
 3284: 
 3285: Clicking a pie slice or legend entry on C</pie> navigates to the table
 3286: view with C<f=cat_col:eq:label> appended, so the user can inspect the
 3287: rows behind any slice without manually typing a filter.

 3289: =head1 COMMON PITFALLS
 3290: 
 3291: These are the most common mistakes when working with this controller.
 3292: 
 3293: =over 4
 3294: 
 3295: =item B<SQLite files must use the .sql extension, not .sqlite>
 3296: 
 3297: C<Database::Abstraction> (the data-reading library) probes for a file called
 3298: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 3299: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 3300: rename it to C<inventory.sql> or it will not appear in the file browser and
 3301: will return 404 when opened.
 3302: 
 3303: =item B<Filter values that contain a colon still work>
 3304: 
 3305: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 3306: if your value itself contains a colon (for example, a time like C<14:30:00>),
 3307: the filter still works because the C<col:op:val> spec is split on the B<first
 3308: two> colons only -- the rest of the string becomes the value.
 3309: 
 3310:   # This correctly matches "14:30:00" in the start_time column:
 3311:   ?f=start_time:eq:14:30:00
 3312: 
 3313: =item B<Left join keeps only the FIRST matching right-table row>
 3314: 
 3315: When the right table has two rows with the same join key, only the first one
 3316: (in file order) is used.  The second is silently ignored.  If you need all
 3317: matches, consider pre-processing your data so join keys are unique.
 3318: 
 3319: =item B<Export format comes from the filename extension, not a Content-Type header>
 3320: 
 3321: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 3322: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 3323: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 3324: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 3325: ignored entirely.
 3326: 
 3327: =item B<Template Toolkit variables starting with underscore are silently dropped>
 3328: 
 3329: If you add a stash variable with a name starting with C<_> (for example,
 3330: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 3331: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 3332: is active.  Always use names that start with a letter.
 3333: 
 3334: =item B<_apply_filter_spec always passes all records through for unknown operators>
 3335: 
 3336: If you pass an operator that is not in the supported list (for example C<regex>
 3337: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 3338: error is produced.  This is intentional so that future operators can be added
 3339: without breaking existing clients that read a wider response.
 3340: 
 3341: =item B<Uploaded files are evicted automatically, but not immediately>
 3342: 
 3343: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 3344: application home directory.  C<Database::BI> evicts upload subdirectories
 3345: whose modification time is older than 24 hours B<on every server startup>.
 3346: Between restarts, files accumulate.  For an immediate full purge (regardless
 3347: of age), post to C<POST /uploads/clear> or click the "Clear upload cache"
 3348: button in the UI.
 3349: 
 3350: =item B<Open C<data/> tables by name; open other files by absolute path>
 3351: 
 3352: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 3353: To open a file from anywhere else on the filesystem, use C<open_file>
 3354: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 3355: are not interchangeable.
