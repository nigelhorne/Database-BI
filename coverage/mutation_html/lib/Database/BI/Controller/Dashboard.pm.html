 2326: =head1 COMMON PITFALLS
 2327: 
 2328: These are the most common mistakes when working with this controller.
 2329: 
 2330: =over 4
 2331: 
 2332: =item B<SQLite files must use the .sql extension, not .sqlite>
 2333: 
 2334: C<Database::Abstraction> (the data-reading library) probes for a file called
 2335: C<tablename.sql> when it wants to open a SQLite database.  It does B<not>
 2336: look for C<.sqlite> or C<.db3>.  If your file is called C<inventory.sqlite>,
 2337: rename it to C<inventory.sql> or it will not appear in the file browser and
 2338: will return 404 when opened.
 2339: 
 2340: =item B<Filter values that contain a colon still work>
 2341: 
 2342: A date like C<2025-01-15> contains hyphens, not colons, so it is fine.  But
 2343: if your value itself contains a colon (for example, a time like C<14:30:00>),
 2344: the filter still works because the C<col:op:val> spec is split on the B<first
 2345: two> colons only -- the rest of the string becomes the value.
 2346: 
 2347:   # This correctly matches "14:30:00" in the start_time column:
 2348:   ?f=start_time:eq:14:30:00
 2349: 
 2350: =item B<Left join keeps only the FIRST matching right-table row>
 2351: 
 2352: When the right table has two rows with the same join key, only the first one
 2353: (in file order) is used.  The second is silently ignored.  If you need all
 2354: matches, consider pre-processing your data so join keys are unique.
 2355: 
 2356: =item B<Export format comes from the filename extension, not a Content-Type header>
 2357: 
 2358: When using C<POST /export> to save a file to disk, the format (CSV or SQLite)
 2359: is determined by the extension of the C<filename> parameter.  C<.csv> produces
 2360: a CSV file; C<.sql> produces a SQLite database.  Any other extension returns
 2361: HTTP 415 (Unsupported Media Type).  The C<Content-Type> request header is
 2362: ignored entirely.
 2363: 
 2364: =item B<Template Toolkit variables starting with underscore are silently dropped>
 2365: 
 2366: If you add a stash variable with a name starting with C<_> (for example,
 2367: C<_tmp> or C<_result>), Template Toolkit will silently produce an empty string
 2368: when the template tries to read it.  This is a TT quirk when C<TRIM =E<gt> 1>
 2369: is active.  Always use names that start with a letter.
 2370: 
 2371: =item B<_apply_filter_spec always passes all records through for unknown operators>
 2372: 
 2373: If you pass an operator that is not in the supported list (for example C<regex>
 2374: or C<like>), the filter is treated as a no-op and B<all rows are returned>.  No
 2375: error is produced.  This is intentional so that future operators can be added
 2376: without breaking existing clients that read a wider response.
 2377: 
 2378: =item B<Uploading a file does not clean up automatically>
 2379: 
 2380: Files uploaded via C<POST /upload> are stored in C<.uploads/> under the
 2381: application's home directory and are B<never deleted automatically>.  They
 2382: accumulate until you manually remove the C<.uploads/> directory.  This is
 2383: intentional for a single-user local tool, but you should be aware of it on
 2384: long-running servers.
 2385: 
 2386: =item B<Open C<data/> tables by name; open other files by absolute path>
 2387: 
 2388: The C<view> action (C<GET /view/:table>) only looks inside C<data_dir>.
 2389: To open a file from anywhere else on the filesystem, use C<open_file>
 2390: (C<GET /open?path=/abs/path>).  The two routes use different URL schemes and
 2391: are not interchangeable.
