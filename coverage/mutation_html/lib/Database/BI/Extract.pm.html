  162: =head1 NAME
  163: 
  164: Database::BI::Extract -- SQLite materialisation cache for Database::BI
  165: 
  166: =head1 SYNOPSIS
  167: 
  168:   use Database::BI::Extract;
  169: 
  170:   my $cache = Database::BI::Extract->new(model_dir => '.bi');
  171: 
  172:   # Check cache
  173:   my $path = $cache->get($spec, $mtime, $size);
  174:   unless ($path) {
  175:       my $bytes = ...; # build the SQLite file
  176:       $path = $cache->put($spec, $mtime, $size, $bytes);
  177:   }
  178: 
  179: =head1 DESCRIPTION
  180: 
  181: Stores SQLite materialisation files (extracts) under C<model_dir/extracts/>,
  182: or under F<database-bi-extracts/> in the cache directory when one is set (see
  183: L</new>).
  184: The cache key is an MD5 of the dataset spec, its source mtime, and its size.
  185: Deleting the extracts directory leaves the application fully functional.
  186: 
  187: The application reads the extract of an accelerated dataset through C<get>,
  188: and C<script/bi-extract> builds one through C<put>; see
  189: L<Database::BI/Accelerated datasets>.  The caller decides when to build an
  190: extract, and the class only stores and finds the bytes.
  191: 
  192: =head1 METHODS
  193: 
  194: =head2 new
  195: 
  196: =head3 API SPECIFICATION
  197: 
  198: =head4 INPUT
  199: 
  200: 	{
  201: 		model_dir => 'string',   # extracts live in <model_dir>/extracts/ when no cache directory is set
  202: 		dir       => 'string',   # optional; the folder itself, used as given: nothing below is read
  203: 		cache_dir => 'string',   # optional; read through Object::Configure (below)
  204: 		config    => 'hashref',  # optional; the application's config (default: database_bi.conf is read)
  205: 		home      => 'string',   # optional; the folder a relative cache_dir in config is under
  206: 	}
  207: 
  208: The cache directory is the first of these that is set (see
  209: L<Database::BI::CacheDir>): C<cache_dir> through L<Object::Configure> (its
  210: config files, then C<Database__BI__Extract__cache_dir>; the C<cache_dir>
  211: argument is what those fall back on), C<$ENV{CACHEDIR}>, C<$ENV{CACHE_DIR}>,
  212: C<cache_dir> in F<database_bi.conf>.  The extracts are then kept in its
  213: F<database-bi-extracts/> folder, never in it directly, because C<evict> removes
  214: every C<.db> file in the folder it uses.
  215: 
  216: =head4 OUTPUT
  217: 
  218: A C<Database::BI::Extract> object.  Croaks C<model_dir is required> when
  219: neither C<model_dir> nor a cache directory is set.  Nothing is created on disc
  220: until C<put>.
