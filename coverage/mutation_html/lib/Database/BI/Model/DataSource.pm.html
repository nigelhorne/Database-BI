  454: =head1 DESCRIPTION
  455: 
  456: C<Database::BI::Model::DataSource> is a thin, table-agnostic adapter that
  457: wraps L<Database::Abstraction> and exposes three accessors (C<fetch_all>,
  458: C<columns>, C<id_column>) used by the controller.
  459: 
  460: L<Database::Abstraction> is a read-only ORM that discovers data files
  461: (CSV, PSV, SQLite, XML, etc.) automatically from a directory based on the
  462: calling class name.  C<DataSource> generates an ephemeral subclass at
  463: construction time so callers never interact with L<Database::Abstraction>
  464: directly.  To swap the backend for L<Database::Join> in Phase 2, only the
  465: C<open_table> helper in C<Database::BI> needs to change; the controller and
  466: C<DataSource> are untouched.
  467: 
  468: C<_detect_file_info> peeks at the first header line of CSV/PSV files to
  469: extract the correct separator character, the primary-key column name, and
  470: the full ordered column list.  Without this, two silent L<Database::Abstraction>
  471: defaults corrupt every result: C<sep_char> defaults to C<'!'> (turning a
  472: comma-separated file into a single-field table) and C<id> defaults to
  473: C<'entry'> (causing every row to be discarded when no C<entry> column
  474: exists).
  475: 
  476: Result filtering (C<eq>, C<contains>, C<gt>, etc.) is performed at the
  477: controller layer by C<Dashboard::_apply_filter_spec> after C<fetch_all>
  478: returns.  C<DataSource> itself is filter-unaware.
  479: 
  480: All user-visible strings and exception messages are keyed through the
  481: C<%MESSAGES> dictionary and routed via C<_msg()>, making every diagnostic
  482: replaceable by an i18n object at instantiation time.
  483: 
  484: =head1 COMMON PITFALLS
  485: 
  486: These are the most common mistakes when using C<DataSource>.
  487: 
  488: =over 4
  489: 
  490: =item B<SQLite databases must use .sql as their file extension>
  491: 
  492: C<Database::Abstraction> looks for SQLite databases with the C<.sql> extension.
  493: It does B<not> recognise C<.sqlite>, C<.sqlite3>, or C<.db3>.  If you have a
  494: file called C<inventory.sqlite>, rename it to C<inventory.sql> before passing
  495: it to C<DataSource>.
  496: 
  497: =item B<The table name is always lowercased>
  498: 
  499: The constructor lowercases the C<table> argument before using it.  Passing
  500: C<table =E<gt> 'Sales'> and C<table =E<gt> 'sales'> both look for
  501: C<sales.csv> (or C<sales.sql>, etc.).  The matching is case-insensitive on the
  502: table name but B<case-sensitive on the directory path>.
  503: 
  504: =item B<CSV files with the wrong separator appear as one giant field per row>
  505: 
  506: C<Database::Abstraction> defaults to C<!> (exclamation mark) as its field
  507: separator.  A standard comma-separated CSV file will look like one big field
  508: per row (for example, C<1,Widget A,North,100>) because the library never sees
  509: the commas as separators.  C<DataSource> fixes this automatically by reading
  510: the first line of the file and detecting the actual separator.  If you bypass
  511: C<DataSource> and call C<Database::Abstraction> directly, you B<must> pass
  512: C<sep_char =E<gt> ','> yourself.
  513: 
  514: =item B<A table with no "entry" column returns zero rows (without DataSource)>
  515: 
  516: C<Database::Abstraction> uses C<entry> as its default primary-key column name.
  517: When slurping a CSV, it discards any row where C<$row-E<gt>{entry}> is
  518: undefined.  Because most CSV files do not have an C<entry> column, B<all rows
  519: are silently discarded>.  C<DataSource> prevents this by reading the actual
  520: first column name from the CSV header and passing it as C<id>, and also by
  521: setting C<no_entry =E<gt> 1> so all rows are kept as an ordered array.
  522: 
  523: =item B<columns() returns undef for SQLite and XML files>
  524: 
  525: C<columns()> only returns an arrayref for file formats where the header order
  526: is visible before data is read (CSV and PSV).  For SQLite and XML files it
  527: returns C<undef>.  Always check: C<if ($source-E<gt>columns) { ... }>.  The
  528: controller falls back to putting C<id_column> first and then sorting the rest
  529: alphabetically when C<columns()> is C<undef>.
  530: 
  531: =item B<XML elements named "name", "id", or "key" cause parse failures>
  532: 
  533: C<XML::Simple> (used by C<Database::Abstraction> for XML files) automatically
  534: turns a child element called C<name>, C<id>, or C<key> into a hash key instead
  535: of keeping it as an array element.  This breaks the expected data structure.
  536: Use different element names in your XML: for example, C<E<lt>skuE<gt>>,
  537: C<E<lt>labelE<gt>>, or C<E<lt>codeE<gt>> instead of C<E<lt>idE<gt>> and
  538: C<E<lt>nameE<gt>>.
  539: 
  540:   <!-- WRONG: these element names trigger XMLin key-folding -->
  541:   <items>
  542:     <item><id>1</id><name>Widget</name></item>
  543:   </items>
  544: 
  545:   <!-- CORRECT: use neutral element names -->
  546:   <items>
  547:     <item><sku>1</sku><label>Widget</label></item>
  548:   </items>
  549: 
  550: =item B<fetch_all returns an empty arrayref, not undef, for an empty table>
  551: 
  552: When a table exists but contains no data rows, C<fetch_all> returns C<[]> (an
  553: empty arrayref), not C<undef>.  Check with C<scalar @{$records}>, not with
  554: C<defined $records> or C<$records>.
  555: 
  556: =back
  557: 
  558: =head1 LIMITATIONS
  559: 
  560: =over 4
  561: 
  562: =item *
  563: 
  564: Only read operations are supported.  Write-back is not in scope.
  565: 
  566: =item *
  567: 
  568: One C<DataSource> instance corresponds to exactly one table.  Multi-table
  569: left joins are composed at the controller layer by C<Dashboard::_left_join>;
  570: C<Database::Join> (Phase 2) is not yet in use.
  571: 
  572: =item *
  573: 
  574: The ephemeral backend class is generated into a package namespace
  575: (C<Database::BI::_DB::*>) that persists for the lifetime of the process.
  576: Instantiating two C<DataSource> objects for the same table name reuses
  577: the same ephemeral class.
  578: 
  579: =item *
  580: 
  581: The C<i18n> object, if supplied, must implement C<maketext($key, @args)>
  582: compatible with L<Locale::Maketext>.
  583: 
  584: =back
