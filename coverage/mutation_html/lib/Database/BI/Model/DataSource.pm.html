  370: =head1 NAME
  371: 
  372: Database::BI::Model::DataSource - Table-agnostic adapter around Database::Abstraction
  373: 
  374: =head1 VERSION
  375: 
  376: This document describes Database::BI::Model::DataSource version 0.01.
  377: 
  378: =head1 SYNOPSIS
  379: 
  380:     use Database::BI::Model::DataSource;
  381: 
  382:     my $source = Database::BI::Model::DataSource->new(
  383:         directory => '/path/to/data',
  384:         table     => 'sales',
  385:     );
  386: 
  387:     my $records = $source->fetch_all;   # arrayref of hashrefs
  388: 
  389:     for my $row (@{$records}) {
  390:         printf "%s: %s\n", $row->{product}, $row->{amount};
  391:     }
  392: 
  393:     # With an i18n object (must implement maketext):
  394:     my $source = Database::BI::Model::DataSource->new(
  395:         directory => '/path/to/data',
  396:         table     => 'sales',
  397:         i18n      => My::I18N::Handle->new,
  398:     );
  399: 
  400: =head1 DESCRIPTION
  401: 
  402: C<Database::BI::Model::DataSource> is a thin, table-agnostic adapter that
  403: wraps L<Database::Abstraction> and exposes three accessors (C<fetch_all>,
  404: C<columns>, C<id_column>) used by the controller.
  405: 
  406: L<Database::Abstraction> is a read-only ORM that discovers data files
  407: (CSV, PSV, SQLite, XML, etc.) automatically from a directory based on the
  408: calling class name.  C<DataSource> generates an ephemeral subclass at
  409: construction time so callers never interact with L<Database::Abstraction>
  410: directly.  To swap the backend for L<Database::Join> in Phase 2, only the
  411: C<open_table> helper in C<Database::BI> needs to change; the controller and
  412: C<DataSource> are untouched.
  413: 
  414: C<_detect_file_info> peeks at the first header line of CSV/PSV files to
  415: extract the correct separator character, the primary-key column name, and
  416: the full ordered column list.  Without this, two silent L<Database::Abstraction>
  417: defaults corrupt every result: C<sep_char> defaults to C<'!'> (turning a
  418: comma-separated file into a single-field table) and C<id> defaults to
  419: C<'entry'> (causing every row to be discarded when no C<entry> column
  420: exists).
  421: 
  422: Result filtering (C<eq>, C<contains>, C<gt>, etc.) is performed at the
  423: controller layer by C<Dashboard::_apply_filter_spec> after C<fetch_all>
  424: returns.  C<DataSource> itself is filter-unaware.
  425: 
  426: All user-visible strings and exception messages are keyed through the
  427: C<%MESSAGES> dictionary and routed via C<_msg()>, making every diagnostic
  428: replaceable by an i18n object at instantiation time.
  429: 
  430: =head1 LIMITATIONS
  431: 
  432: =over 4
  433: 
  434: =item *
  435: 
  436: Only read operations are supported.  Write-back is not in scope.
  437: 
  438: =item *
  439: 
  440: One C<DataSource> instance corresponds to exactly one table.  Multi-table
  441: left joins are composed at the controller layer by C<Dashboard::_left_join>;
  442: C<Database::Join> (Phase 2) is not yet in use.
  443: 
  444: =item *
  445: 
  446: The ephemeral backend class is generated into a package namespace
  447: (C<Database::BI::_DB::*>) that persists for the lifetime of the process.
  448: Instantiating two C<DataSource> objects for the same table name reuses
  449: the same ephemeral class.
  450: 
  451: =item *
  452: 
  453: The C<i18n> object, if supplied, must implement C<maketext($key, @args)>
  454: compatible with L<Locale::Maketext>.
  455: 
  456: =back
  457:
