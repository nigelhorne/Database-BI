  113: =head1 DESCRIPTION
  114: 
  115: Finds the county each point is in and returns its outline as a GeoJSON
  116: Feature, for L<HTML::OSM>'s C<add_geojson>.  The outlines come from
  117: OpenStreetMap's Nominatim reverse lookup, through the same throttled user agent
  118: as the geocoder (L<Database::BI::Model::Geocode/nominatim_ua>), so the two
  119: together never ask more than once a second.
  120: 
  121: Only the point is sent, rounded to three decimal places (about 110 metres).
  122: Every answer is cached: a point with the outline it is in, and the outline
  123: itself.  A point inside an outline already known is matched here, without a
  124: request, so many points in one county cost one lookup.
  125: 
  126: A county here is the division of a country below its states, whose place rank
  127: in Nominatim depends on the country: 12 (a US county or independent city, an
  128: English county, a German Landkreis, a French departement) unless the country is
  129: listed otherwise: 10 for India, Bangladesh, China and Spain (district,
  130: prefecture, province), 8 for Kenya.  C<ranks> adds or changes countries.
  131: Anything else Nominatim answers is taken as "no county here" and remembered as
  132: such.  A country with nothing at its rank (Australia, Brazil, Japan) gets no
  133: outlines.
  134: 
  135: Each reply names the point's country, so a point is asked at the zoom of the
  136: last country seen, and asked again when its own country wants another rank.
  137: An outline is kept with the rank it was accepted at; when C<ranks> changes, the
  138: points it covered are asked again.
