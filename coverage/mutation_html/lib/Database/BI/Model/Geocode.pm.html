  207: =head1 DESCRIPTION
  208: 
  209: C<Geo::Coder::Free> resolves a place name to a C<Geo::Location::Point>.  A table
  210: column holds something less tidy: values repeated thousands of times, blank cells,
  211: numbers that drifted in from an adjacent column.  This module does the three things
  212: the column then needs.
  213: 
  214: =over 4
  215: 
  216: =item B<Ask once per distinct value.>
  217: 
  218: The column is reduced to a set before any lookup happens.  A repeated city name
  219: costs one lookup, so a 100,000-row file with a dozen cities costs twelve lookups,
  220: not 100,000.
  221: 
  222: =item B<Refuse a value that is not a location before any backend sees it.>
  223: 
  224: C<< $geocoder->valid_location($value) >> is the gate the geocoder's own guard
  225: applies before looking anything up.  This module asks the same question first, so
  226: a pure-digit string (a row number that ended up in the wrong column), an empty
  227: cell, or a Perl reference is counted and reported as skipped rather than sent to
  228: a backend that would reject it anyway.
  229: 
  230: =item B<Look the rest up without letting one value end the batch.>
  231: 
  232: The batch is requested with C<< on_error => 'undef' >>.  A value the geocoder
  233: refuses after the pre-filter is a miss; a backend that throws an exception is
  234: still a throw, because nothing here wraps the geocoder in an C<eval>.
  235: 
  236: =back
  237: 
  238: The counts the module returns add up, always.
  239: 
  240:     skipped + cached + attempted + not_attempted  ==  distinct
  241:     resolved + unresolved                         ==  cached + attempted
  242: 
  243: C<lookups> is the number the geocoder itself reports for the batch.  With
  244: C<Geo::Coder::Free> 0.48 and later it may be lower than C<attempted>, because
  245: the geocoder counts database reads and a value it answered from a warm process
  246: cache costs zero reads.  It never exceeds C<attempted>.
  247: 
  248: =head2 The cache
  249: 
  250: A cache entry is a C<[lat, lon]> arrayref for a place that resolved, or the
  251: scalar C<0> for a place that was looked up and not found.  That C<0> sentinel
  252: prevents a column of unresolvable values from being retried on every page
  253: request.
  254: 
  255: The cache is passed per call and returned per call.  The caller's hashref is
  256: never modified: a request that dies part way through cannot leave a half-written
  257: cache behind.  The controller is responsible for persisting the returned cache,
  258: which keeps the C<model_dir>-inside-C<data_dir> guard in the one place that
  259: already owns it.
  260: 
  261: A previously stored cache is used even when the geocoder is not available.
  262: Places already resolved continue to be plotted; only new lookups are unavailable.
  263: 
  264: =head2 Without the geocoder
  265: 
  266: C<Geo::Coder::Free> is a recommended dependency, not a required one.  It is
  267: loaded the first time it is needed, not at compile time.  When it is absent or
  268: older than the minimum version:
  269: 
  270: =over 4
  271: 
  272: =item *
  273: 
  274: C<< $geocode->geocoder_available() >> returns C<(0, $reason)>.
  275: 
  276: =item *
  277: 
  278: C<resolve_column> and C<resolve_values> still return a complete result: all
  279: values are placed in C<not_attempted>, cached answers are still plotted, and
  280: the C<error_map_geocoder_missing> message explains the situation.
  281: 
  282: =item *
  283: 
  284: Nothing croaks.  The page renders with whatever the cache already holds.

  286: =back

  339: =head2 resolve_column

  348: resolution as L</resolve_values>, then adds per-marker row counts and the

  352:

  354: 
  355:     \@rows          => arrayref of hashrefs, required

  361: C<\@rows> is the full record set as returned by the pipeline.  Rows that are
  362: not hashrefs produce an C<undef> cell, which is classified as skipped.
  363: 
  364: C<$column_name> must be a non-empty string.  It is used as a hash key; it is

  367: 
  368: C<cache> holds the already-known answers for this column.  Entries are either

  371: updated copy.
  372: 
  373: C<region> is passed straight through to the geocoder as a country hint.  It
  374: is not derived from the Accept-Language header, because a language is not a
  375: country.
  376: 
  377: C<max> is counted in new lookups, not rows.  A cached answer costs nothing
  378: and does not count toward it.  Values held back by the cap go into
  379: C<not_attempted> and are not stored in the cache, so the next request picks
  380: them up.

 1285: =item B<The cache sentinel 0 is not "false -- never looked up".>
 1286:

 1300: 
 1301: A value like C<'42'> fails C<valid_location()> and goes into C<@skipped>.  It
 1302: is never stored in the cache.  This is the correct behaviour for a row number
 1303: that ended up in the wrong column, but it surprises callers who expect every

 1318:

 1321: not count either.

 1507:         (lat, lon) = coordinates(BATCH(v))
 1508:         if defined(lat) and defined(lon):
 1509:             CACHE'(v)  = [lat, lon]
 1510:             POINTS'(v) = { lat, lon, backend? }
 1511:         else:
 1512:             CACHE'(v)  = 0
 1513:             UNRESOLVED_NEW += {v}

 1516: 
 1517:     skipped + cached + attempted + not_attempted = distinct(V)
 1518:     resolved + unresolved = cached + attempted
 1519:     resolved  = |CACHED_RESOLVED| + |ATTEMPT âˆ© POINTS'|
 1520:     unresolved = |CACHED_UNRESOLVED| + |ATTEMPT \ POINTS'|

 1528: =head2 resolve_column -- row augmentation
 1529: 
 1530: Given the output R of _resolve applied to the column's cell sequence CELLS:
 1531: 
 1532:     row_count  : Value -> N   where row_count(v) = |{ i | CELLS[i] = v }|
 1533:     first_row  : Value -> N   where first_row(v)  = min{ i | CELLS[i] = v }
 1534: 
 1535:     For each v in dom(R.points):
 1536:         R.points(v).rows      = row_count(v)
 1537:         R.points(v).first_row = first_row(v)
 1538: 
 1539:     R.markers = [ { value: v, ...R.points(v) }
 1540:                   | v <- sort_by(first_row, dom(R.points)) ]
 1541: 
 1542:     R.counts.rows     = |CELLS|
 1543:     R.counts.plotted  = sum{ row_count(v) | v in dom(R.points) }
 1544:     R.counts.unusable = R.counts.rows - R.counts.plotted
