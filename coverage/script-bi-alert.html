1#!/usr/bin/env perl
2# bi-alert -- Digest and threshold CLI for Database::BI
3#
4# Evaluates the measures of one or more saved analyses, prints a digest to
5# STDOUT for each, and exits 1 when a threshold condition is crossed.  It makes
6# no mail or network call: delivery is the caller's job, which is what lets cron
7# (or a wrapper that pipes STDOUT into mail, a webhook or a ticket) decide what
8# an alert is.  Scheduling is likewise cron's.
9#
10# Several checks in one run are the normal case: --analysis may be repeated, and
11# --threshold may be repeated and may name its analysis, so one cron line can
12# watch several measures across several saved analyses.  Every (analysis,
13# threshold) pair is reported, throttled and recovered on its own -- the state
14# file is keyed by both -- and one run is one delivery, with all the
15# announcements in the text.
16#
17# A threshold that stays crossed is not news a second time, so --suppress gives
18# an (analysis, threshold) pair a throttle: the first crossing is announced, and
19# repeats inside the period are not.  The memory for that is one small JSON file
20# in the model directory, written only when --suppress is used (or once such a
21# file exists); with no --suppress the script behaves exactly as it always has
22# and writes nothing.  When the threshold clears, its entry is dropped, so the
23# next crossing alerts straight away rather than staying quiet about it.
24#
25# The end of a crossing is news as well, and --recovery announces it: the run
26# that sees the threshold clear prints THRESHOLD RECOVERED and exits 3, so a
27# wrapper that mails on a non-zero status mails the recovery too.  The state
28# file is what makes this possible, since an entry is the record of a crossing
29# that was announced: finding one is what tells this run that an incident has
30# ended rather than that a threshold was never crossed.  That is also why
31# --recovery keeps that file even with no --suppress to throttle, and why the
32# recovery is said once per crossing rather than on every run after it.
33#
34# Delivery is optional as well: --notify-cmd runs a command when, and only
35# when, something is announced, with the run's own text on STDIN and the
36# verdict in the environment.  That makes a cron line one command instead of a
37# shell wrapper around this one, and it keeps the rule the script has always
38# had -- nothing leaves the machine unless somebody asked it to.
39#
40# Usage:
41#   bi-alert --analysis <id> [--analysis <id> ...]
42#             [--threshold <alias>:<op>:<value>] [--threshold <analysis>:<alias>:<op>:<value> ...]
43#             [--suppress <duration>] [--state-file <path>] [--recovery]
44#             [--notify-cmd <command>]
45#             [--model-dir <dir>] [--data-dir <dir>] [--dry-run]
46#
47# Exit codes:  0 = ok / nothing announced (not crossed, or already announced)
48#              1 = a threshold crossed, and is announced
49#              2 = error (bad args, analysis not found, data unavailable)
50#              3 = a crossing that was announced has ended, and is announced
51#                  as a recovery (--recovery); 1 wins if a run announces both
